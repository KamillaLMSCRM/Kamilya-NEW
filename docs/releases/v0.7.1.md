# Release Notes — 0.7.1

**Product version:** 0.7.1

**Git tag:** `v0.7.1`

**Date:** 2026-09-17

## Для клиентов

- Создание и изменение подразделения больше не завершается ложной ошибкой
  после успешного сохранения.
- После сохранения пользователь сразу получает актуальное подразделение с его
  уровнем и полным путём в структуре.
- Должность сотрудника остаётся обязательной, а подразделение — необязательным;
  существующую должность можно выбрать и без предварительного выбора отдела.

## Причина исправления

- Ответ для созданного или изменённого узла строился после завершения
  транзакции. Вместе с транзакцией завершался tenant-scoped RLS-контекст, поэтому
  повторное чтение не видело только что сохранённую строку и возвращало HTTP 500.
- В 0.7.1 ответ строится в той же RLS-транзакции до commit, а наружу возвращается
  уже материализованный tenant-safe результат.

## Проверка релиза

- Полный database-free API suite: `2763 passed`, `487 skipped`.
- Контур структуры, staff import, training log и evidence: `103 passed`,
  `3 skipped`.
- Полный frontend suite: `115` файлов, `613` тестов; ESLint, TypeScript и
  production build прошли.
- Python quality baseline: `ruff=1061`, `mypy=2238`.
- Migration `0161`, RLS/FORCE RLS, depth/cycle/cross-tenant checks и cleanup
  повторно прошли в отдельной Supabase DEV схеме без изменения shared public.
- Точный GitHub CI, immutable image и production synthetic smoke фиксируются
  для release SHA перед объявлением GO.

## Развёртывание и откат

- Новая миграция не требуется: production остаётся на `0161`.
- API и три worker обновляются одним immutable image; frontend публикуется с тем
  же release SHA для сохранения версионной идентичности.
- Откат приложения — на `v0.7.0`; структура и данные migration `0161` остаются
  без изменений.
