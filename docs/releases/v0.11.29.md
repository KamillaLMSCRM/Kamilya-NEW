# Release Notes — 0.11.29

**Product version:** 0.11.29. Candidate; tag and GitHub Release not published.
**Git tag:** `v0.11.29` — planned, not published.

Узкое исправление штатной очистки disposable tenant после живой приёмки28.
В production173 владелец SECURITY DEFINER без BYPASSRLS видит tenant при
SELECT, но FOR UPDATE получает false RLS filter. Первая reminder-purge функция
отклоняет правильный slug до любых удалений; обе тестовые организации сохранены.

Additive0174 добавляет только owner-only UPDATE USING для блокировки exact
app.tenant_id при superadmin-контексте и допустимом session_user. Защищённый
tenant kamilya исключён; WITH CHECK(false) запрещает реальный UPDATE.
Прямые runtime grants, FORCE RLS, owners, memberships и helper bodies не меняются.

Изолированный Supabase DEV gate воспроизвёл filtered-zero на NOLOGIN/non-bypass
временном владельце и прошёл10 проверок: lock, negative contexts, forbidden
writes, неизменность строк, downgrade/reapply. Схема, роль и membership откатились;
public catalog/revision не менялись. Это не полный tenant lifecycle proof.

План выпуска: DEV173->174 через явную repair-фазу; точный CI/image и защищённый
production173->174 с fresh backup/restore и application rollback28 без schema
downgrade. Backend API/3workers только; production native frontend28 остаётся
на64c8bfeb с уже проверенным UI/API контрактом и включённым флагом. После выпуска
нормальный API DELETE существующих synthetic A/B, fresh404, независимое отсутствие
и сохранность постоянного QA обязательны. Пока это NO_GO для финальной приёмки.

Дополнительно закрепляется уже проверенное исправление controller timeout;
оно не меняет immutable native28, helper, доступы или permissions.
Нет voice/STT/LLM/mail, customer mutations, DNS/Proxmox/landing/tier changes.
