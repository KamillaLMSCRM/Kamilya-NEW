## Source-preserving multiformat generation

An identical warehouse procedure in Markdown retained three priority/deadline/
approver relationships; the production45 PDF counterpart silently lost them while
being labelled publishable. The remote converter retained all cell words but
flattened the grid. The original rejected draft is retained, unpublished and
unassigned; the failed first run is not discarded from the benchmark.

Restore ruled tables by cross-checking coordinates in the same original PDF blob
against one exact flattened text occurrence. Preserve every surrounding paragraph;
never infer missing cells or invoke another model. Ambiguous, incomplete or
unsupported recovery is terminal rather than silently returning text-only data.
This covers verified ruled digital tables, not universal borderless/scanned-table
fidelity. The existing converter service and its authentication are unchanged.

## Boundaries and remaining acceptance

Five frozen synthetic cases: short TXT, medium Markdown, identical medium PDF,
complex Markdown and an explicitly unresolved negative TXT source. Ordinary QA
methodologist generation/review/publication/assignment and learner completion
must be separately documented. First-run wall-clock measurements and retained
facts are not a paired human productivity or learning-effectiveness study.

API and existing workers plus native frontend are the intended deployment scope.
No database migration, converter rebuild/restart, model, budget, feature flags,
provider tier, resources, billing, DNS, landing, pricing, voice or antivirus
activation change. Existing completed QA history is preserved; current test
courses and outcomes are retained rather than purged.
