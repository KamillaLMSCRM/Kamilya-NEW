# Release Notes — 0.11.16

**Release date:** 2026-09-29

**Product version:** 0.11.16

**Git tag:** `v0.11.16`

## Added

- Methodologists can inspect every recurring course and program period, see its
  original and current deadline, and open the append-only deadline-change
  history.
- An active participant deadline can be changed only with a timezone-aware date
  and a meaningful 20–1000 character reason.
- Native course occurrences retain an exact content-release and enrollment
  evidence anchor; program certificates select the exact assignment enrollment.

## Fixed

- Active program periods become overdue after their effective deadline, matching
  the training journal.
- A deadline change reschedules only an unattempted queued reminder. Sent,
  attempted, failed and delivery-uncertain reminders are never rewritten.
- Superadmin support impersonation no longer writes a platform operator into a
  tenant-owned source-actuality author field; the audit event still identifies
  the actual operator.

## Security and data integrity

- Revision `0167` adds FORCE RLS and runtime SELECT/INSERT-only access for
  append-only participant deadline events.
- Runtime deletion of native course occurrences is revoked. Original target,
  learner, sequence, dates and release identity are immutable; enrollment may
  be linked once and cannot later be cleared or rebound.
- Migration fails closed if a non-skipped legacy occurrence lacks a reciprocal
  enrollment and content-release anchor.

## Verification required

- Full API suite, frontend suite, lint, typecheck and production build.
- Isolated Supabase DEV migration upgrade, malformed-backfill rejection, FORCE
  RLS/cross-tenant checks, PostgreSQL row lock, append-only event behavior,
  enrollment immutability, safe reminder rescheduling, guarded downgrade and
  cleanup.
- Exact-SHA CI, DEV deployment/readback, production backup and revision `0167`
  rollout, synchronized API/workers/frontend, synthetic methodologist journey
  and cleanup.

## Operations

- Database migration: additive revision `0167`.
- Application rollback: immutable `0.11.15` / Git SHA
  `f3803d5bcf9058a82626b59d76fb60c52fbf4f84`.
- Database downgrade is permitted only when no deadline-change events exist;
  otherwise retain the additive schema while rolling the application back.
- No provider plan, billing, DNS or customer-data mutation is authorized.
