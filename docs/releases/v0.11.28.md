# Release Notes — 0.11.28

**Product version:** 0.11.28
**Git tag:** `v0.11.28` — planned, not published
**Date:** 2026-10-02

Кандидат управляемого включения первого текстового сценария рабочего места
методиста: назначение существующего опубликованного курса существующему отделу
через серверный предпросмотр и отдельное явное подтверждение. Голос,
распознавание, общий LLM-разбор и создание/редактирование курса не входят.

Навигация, сборка и пакет выпуска используют один проверяемый флаг. Включённый
native-артефакт допускается только с0.11.28 и явным boolean в новом формате
пакета; старые пакеты и совместимый0.11.27 остаются OFF-only. Восьмиполевой
manifest установленного helper не меняется; Proxmox, права и ключи не нужны.

DEV-контроллер готовит только три существующих флага после проверки финальной
схемы0173 по принятому purge-addendum и точного успешного CI. Новый пакетV3
не меняет прежнийV2/0172. Тарифы Render Free/Vercel Hobby, остальные
настройки и постоянный QA-стенд сохраняются. Наблюдение настроек провайдера
отделено от доказательства работающего пользовательского сценария.

Статус: кандидат, не production GO. Включённый DEV28/eb427100 на public0172:
browser preview/confirm/replay, created1/skipped1, сохранённый прежний срок,
student role и mobile390 PASS. Очистка отдельного populated QA tenant остановилась
на старом FK/ACL дефекте; tenant сохранён, постоянный QA не пересоздавался.
Добавлена0173: узкий superadmin helper, порядок enrollment-before-release и
конечная ошибка без сырого SQL. Изолированный Supabase DEV runtime proof12 PASS:
отказы/ACL/rollback/sentinel/upgrade-downgrade, схема удалена, public неизменна.
Это не доказывает все исторические зависимости tenant. Новый source/CI/DEV173,
нормальная API-очистка и повторная приёмка ещё обязательны.
Production остаётся на совместимом backend0.11.26/schema0169/OFF и frontend0.11.27.
Финальный B-выпуск требует отдельного защищённого169->173 gate, свежего backup,
совместимого application rollback A26 с flags OFF и полной живой приёмки.
Результаты выпуска фиксируются в docs/PRODUCTION_READINESS.md после проверки.
