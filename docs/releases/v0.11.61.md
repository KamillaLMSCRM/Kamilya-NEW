# Release Notes — 0.11.61

Candidate, not yet deployed or accepted. Narrow backend follow-up to the live
structure/Excel acceptance of0.11.60. Native frontend60 remains compatible;
no new frontend release or host cleanup is required for this server-only fix.

## Fixed

Staff-import source references now follow physical columns from the parser's
actual header mapping. A six-column sheet with branchD/departmentE no longer
shows historical branchG/departmentD. Reordered/custom mappings, ignored columns,
split names, absent optional fields and columns beyondZ are covered by regression
tests. Legacy callers without parsed metadata retain their historical defaults.

Repeat-import preview now recognizes equal stable parent keys even when the file
omits the optional parent name. Canonical and compatibility unit actions are
synchronized, and staff diff actions use the actual external identity key.
Deactivated staff produce a blocking review conflict; a locked identity recheck
also rejects offboarding performed after approval, before any commit writes.
No automatic reactivation or new reactivation workflow is introduced.

No identity reassignment, hierarchy transfer, role/right expansion, RLS,
database migration, import mode, model routing/reserve, voice or provider change.
Merged/forward-filled values still reference their parsed row rather than the
original contributing cell; this limitation is not relabeled as corrected.
