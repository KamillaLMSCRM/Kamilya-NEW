# Release Notes — 0.2.0

**Release date:** 2026-08-31  
**Product version:** 0.2.0  
**Git tag:** `v0.2.0`  
**Deployed commit:** resolved by the immutable `v0.2.0` tag at release time

## Summary

Kamilya 0.2.0 expands the methodologist workflow from source materials through
course preparation, assignment, and learner completion. It also establishes a
formal product-version and release-notes contract for future updates.

## Added

- Generate one course from up to five compatible source documents with explicit
  language and topic checks.
- Prepare YouTube captions as an ordinary indexed source document when the
  feature is enabled.
- Request bounded AI-assisted improvements while reviewing course lessons and
  quiz questions.
- Show the current product version and a link to user-facing release notes.
- Let a verified trial owner enter the working methodologist interface
  immediately while retaining a separate tenant-administrator role.

## Changed

- Reordered the methodologist navigation around the real operating sequence:
  materials, course creation, assignment, employees, groups, and results.
- Placed employee structure and employee groups next to each other.
- Restricted finance-specific course templates to explicitly classified
  financial-organization tenants.
- Simplified contextual help and aligned retention guidance with the actions
  actually available to a methodologist.

## Fixed

- Strengthened assignment, group membership, learner-completion, and access
  revocation flows based on full production-style acceptance scenarios.
- Removed a terminal learner action that could appear to do nothing after the
  final lesson.

## Security

- Kept assistant previews tenant-bound and rejected impersonated mutations.
- Preserved verified source provenance and bounded multi-document admission.

## Upgrade / deployment notes

- Database migrations: apply the repository head through the normal fail-closed
  release procedure.
- Environment variables: no version-display variable is required; the cabinet
  reads the version from its application manifest.
- Frontend/backend deploy order: follow the exact-SHA release packet and current
  migration compatibility rules.

## Verification

- Version consistency, application tests, builds, dev acceptance, production
  deployment, and public readback remain release gates until recorded against
  the exact `v0.2.0` commit.

## Rollback

Redeploy the exact previously accepted production SHA and preserve additive
database migrations unless the release packet explicitly proves a safe schema
rollback.
