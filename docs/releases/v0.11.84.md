# Release Notes — 0.11.84

**Product version:** 0.11.84

**Git tag:** `v0.11.84`

New course jobs use the autonomous editorial protocol. Whole-course and physically
blind answer findings enter addressed model editing; a follow-up review evaluates
the complete current course and every earlier material issue. Source and course
fingerprints, literal evidence custody and preserved response receipts prevent
silently carrying an earlier verdict across an edit. Genuine ambiguities of the
source retain specific questions; model, evidence or transport failures do not
become invented source questions.

The source model first reads rules, verifies their interpretation and separately
adds omissions without replacing corrected rules. Its own source corrections and
additions become scoped author alignment goals. Teaching review excludes question
text physically; keyed assessment and blind answer checks remain separate. Compact
coverage verdicts are model judgments, not semantic truth inferred from source IDs.

An automatic content acceptance receipt is bound to the exact persisted course
and its sources in the completed server-owned generation job. Changes invalidate
it. Methodologist publication approval remains explicit; an unchanged accepted
course no longer requires a duplicate manual source-resolution action.

Additive migration 0187 extends the existing runtime-settings key and numeric
constraints for `generation.editorial_max_revisions` (default 3, range 1–5).
The companion `generation.editorial_rules_per_review` setting defaults to128
(range1–128); partitions return every rule exactly once, with source context intact.
Existing overrides and audit history are preserved. Provider routing, credentials,
plans and resources are unchanged; prior review policies retain their own request
and checkpoint identities.

Autonomous editorial output settings use that same audited catalog:
`generation.editorial_luna_max_tokens` (32768; range8192–32768) and
`generation.editorial_deepseek_max_tokens` (65536; range16384–65536).
Their captured effective values enter checkpoint identity; old profile identities
are preserved. Unknown post-dispatch outcomes cannot trigger a hidden reserve
request or retry. Proven pre-dispatch/rejection failures may use the existing
reserve route within the existing whole-invocation deadline.

Historical assessment remarks carry a snapshot of the actual current target.
An unverified latest decision revokes previous repair authority; confirming a
question defect requires a quote from its current owned text. This avoids
editing good revisions to satisfy a stale model allegation.

Local technical verification, model semantic results, exact DEV and production
acceptance are separate evidence. These release notes alone do not establish that
the two original documents have passed the new model cycle or that a deployment
has occurred. Current results belong to the canonical handoff and test ledger.

New policy v34 consolidates all partial observations in the existing final editor
slot before addressed repair; it adds no new critic. Existing v33 jobs retain their
original dispatch and exact-policy acceptance contract. Model acceptance and live
DEV/production gates remain separate from the technical regressions.

The v34 final editor uses one whole-course responsibility instead of inheriting
the assessment-specialist role. Current target snapshots are shared across
observations without losing any finding or proof field. Existing focused source
reviews, independent answer checks and the audited revision default remain.

Addressed v34 evidence correction receives the same owned literal text scope
used by the compiler, including consistent source aliases. Proof correction
retains primary semantic decisions, unresolved holds, source questions and raw
responses; literal custody is not a semantic correctness claim.

The v34 source verifier checks the grammatical attachment of conditions and
applicability in both directions. Author, scoped editor and reviewers preserve
the supplied source meaning rather than replacing a clear clause with an
expected industry rule. A model's misreading remains automatic repair work;
only a genuine unresolved source choice is referred to the source owner.
Logical comparison groups share source/course context within the existing rule
output budget, retaining every rule, scope, target and dependency. Actual native
quality, total token use and latency remain acceptance gates.
