# Release Notes — 0.11.60

**Product version:** 0.11.60
**Git tag:** `v0.11.60`

The combined DEV acceptance additionally exposed an explicit-exclusion hint defect:
a deadline question saying not to discuss retention could require a retention
answer part. Narrow multilingual directive handling is included; original model
input and strict part/citation/conflict validation remain unchanged. The original
failed provider output was not retained, so this is a proven deterministic defect,
not an asserted reconstruction of that model failure.

Live DEV also exposed a worker asyncpg connection reused after its event loop
closed. The worker received generation but could not claim it, leaving a pending
job. Worker initialization now uses a loop-safe NullPool while preserving the
shared session factory and API pool. A real DEV read-only SELECT reproducer
failed before and passed three separate loops afterward; fresh deployed generation
and latency remain release gates. No automatic provider/task replay is introduced.

Combined cabinet reliability and course-quality package. Production publication
and acceptance are pending; exact evidence belongs to the active release plan.

## User-visible changes

- Choose an active company methodologist as a document-source owner, clear the
  owner, save dates and recover input after a validation/network failure.
- Reader Next, sidebar and requested lesson stay synchronized. Learners return
  to their assigned-course list; preview reading does not write learner progress.
  Course/user/role changes clear the prior completion/evidence/quiz state and
  ignore delayed reads and user-action replies belonging to the previous scope.
  Quiz state is also keyed to the current lesson in render: a fast switch cannot
  expose the prior quiz link/pass. Metadata failures show Retry and block lesson
  progression; only a confirmed404 is treated as a lesson without a quiz.
- Mandatory-training action filters track the actual route and can be reset
  without silently retaining the prior dashboard filter.
- Program assignment rejects reversed dates, resets audience/editor state safely,
  and offers only active departments. Existing historical results remain intact.
- Competency creation retains selected course links; link/save responses are
  materialized before the transaction boundary loses tenant-scoped ORM state.
- Position creation chooses an exact organization unit with its breadcrumb,
  rather than recreating a nested department as a legacy root. Explicit UUID,
  explicit unassignment and omitted fields have distinct update semantics.
  Tree-load failures are visible/retryable; ambiguous legacy names fail closed.
- Ordinary lesson/module and course-approval controls retain authoritative saved
  data, reviewer selection, review resume position and a clear terminal decision.
  Native publication requires content rendered by the current clients; invisible
  content blocks alone do not make an empty course publishable.
- Generated questions prioritize workplace steps and critical conditions over
  goal/author/QA boilerplate. A short source is not padded with low-value questions;
  genuine operational privacy/legal rules remain eligible.
- Multipart document answers retain per-dimension evidence and question-bound
  conflict positions. This pre-existing server58 delta is explicitly included
  because frontend59 did not deploy it; it requires fresh live DEV acceptance.
- WhatsApp gateway readiness/transport/malformed-response failures are translated
  without an exception inside logging. The cabinet shows a retry state instead
  of presenting an unavailable channel as ready to initialize. Polling waits for
  its interval rather than immediately repeating on every status object.
- Printable evidence separates the footer rule from its text instead of drawing
  through the italic caption. No evidence content or confirmation status changes.

## Boundaries and release gates

API plus three workers and native frontend are the intended release targets.
No database migration: production revision0181 remains unchanged. Existing DEV
work is preserved in a separate integration commit, not promoted wholesale.
Voice, reserve/model routing, iSpring/advanced authoring, staff-workspace activation,
ASUS, permissions, DNS, provider plans/resources and real customer data are outside
this packet. No external notification channel is activated by these fixes.

Synthetic full-course and isolated DB evidence, failures and corrections are
recorded in docs/plans/2026-10-18_cabinet-combined-release.md. Exact SHA/CI/native
artifact, protected release/readback, changed-path DEV/browser acceptance and
production preservation checks must all pass before the release is called ready.
