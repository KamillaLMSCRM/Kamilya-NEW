# Release Notes — 0.7.0

**Product version:** 0.7.0

**Git tag:** `v0.7.0`

**Date:** 2026-09-17

## Для клиентов

- Структура компании больше не ограничена связкой «филиал → отдел». Можно
  создавать управления, департаменты, отделы, секторы, команды и другие уровни
  вложенности.
- Центральный офис задаётся явным признаком и отображается отдельной отметкой.
- Должность сотрудника обязательна, а подразделение необязательно. Одну
  должность можно использовать в нескольких подразделениях.
- Поддерево можно безопасно переместить: до сохранения система показывает,
  сколько подразделений, должностей и сотрудников будет затронуто.
- Обязательные курсы и программы, назначенные верхнему подразделению,
  распространяются на сотрудников активных дочерних подразделений.

## Проверка релиза

- Полный database-free API suite: `2760 passed, 54 skipped` до финального
  migration-gate исправления; полный набор повторяется для точного release SHA.
- Полный frontend suite: `115` файлов, `613` тестов; ESLint, TypeScript и
  production build прошли.
- Реальная migration `0161` прошла upgrade, downgrade/re-upgrade, tenant RLS,
  FORCE RLS, cross-tenant negatives, depth/cycle checks и cleanup в отдельной
  Supabase DEV схеме. Shared public revision не изменялась.
- GitHub CI, immutable image, production migration и пользовательский smoke
  фиксируются отдельно для точного release SHA.

## Безопасность и данные

- Новые связи между сотрудником и подразделением проверяются внутри tenant.
- Cross-tenant родитель и cross-tenant назначение сотрудника отклоняются базой.
- В приёмке используются только синтетические данные.

## Развёртывание

- Требуется additive migration `0161`.
- Новые переменные окружения и платные ресурсы не требуются.
- Порядок: резервная копия CT125 → migration `0160 → 0161` → API и три worker →
  frontend exact SHA → production readback и synthetic smoke.

## Откат

- Приложение можно вернуть на `v0.6.3`; additive schema `0161` остаётся на месте.
- Downgrade migration разрешён только пока нет v2-размещений, центрального офиса
  или произвольной вложенности. После использования новой структуры безопасный
  откат — только application rollback с сохранением схемы и данных.
