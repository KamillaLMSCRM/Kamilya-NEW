# Release Notes — 0.10.0

**Release date:** 2026-09-22
**Product version:** 0.10.0
**Git tag:** `v0.10.0`

## Для клиентов

Методист может назначить сотруднику уже пройденный курс повторно. Для этого
нужно указать причину. Kamilya создаёт новый цикл обучения с новым лимитом
попыток, а прежнее прохождение, ответы, результат теста, сертификат и документы
подтверждения остаются в истории без изменений.

Новый цикл также начинает прогресс уроков с нуля. Ранее открытые уроки и
завершённые шаги остаются связаны с прежним прохождением и не переносятся в
повторное назначение.

На главном экране методиста появились показатели текущего обучения: ещё не
начали, проходят, завершили, просрочили, не сдали, исчерпали попытки и получили
повторное назначение. Отменённые и заменённые записи не увеличивают текущие
показатели. Их можно увидеть, включив историю в журнале обучения.

## Для методиста

1. Откройте «Назначения и доступ» и выберите опубликованный курс.
2. У нужного сотрудника нажмите «Назначить повторно».
3. Укажите понятную причину и подтвердите действие.
4. Текущий курс появится как новое назначение. Предыдущее прохождение останется
   в журнале и будет видно при включённой истории.

Автоматические назначения по должности, подразделению или периодическому
правилу нельзя повторять этой кнопкой: ими управляет соответствующее правило.

## Проверка качества

- API и UI проверяют точный идентификатор предыдущего назначения, tenant,
  сотрудника, курс, роль методиста и источник назначения.
- Изолированный Supabase DEV-гейт подтвердил FORCE RLS, запрет cross-tenant
  predecessor/actor, защиту истории при downgrade и полную очистку временной
  схемы.
- Database-free API: 3059 passed, 495 integration-only skipped.
- Web: 121 файлов / 664 теста passed; typecheck и production build passed.

## Развёртывание

- Database migration: `0162_manual_reassignment_occurrences.py` — обязательна.
- Новые переменные окружения: не требуются.
- Новые платные ресурсы и изменения тарифов: не требуются.
- Миграция additive и допускает немедленный откат приложения до первого
  повторного назначения. После появления новой истории откат приложения или
  схемы выполняется только по проверенному restore/forward-fix пути: downgrade
  намеренно защищает сохранённые прохождения от удаления.
