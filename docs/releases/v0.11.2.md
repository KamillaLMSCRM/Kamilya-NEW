# Release Notes — 0.11.2

**Release date:** 2026-09-25

**Product version:** 0.11.2

**Git tag:** `v0.11.2`

## Для владельца платформы

Операционная консоль superadmin теперь показывает давление по памяти и диску
хоста, а также независимое состояние трёх рабочих ролей Celery: быстрые задачи,
обработка документов и AI-генерация. Для каждой роли видны ожидаемые, активные
и отсутствующие очереди, поэтому частичный отказ больше не скрывается за общим
числом worker.

При недоступности брокера или неполном ответе контрольной плоскости интерфейс
явно показывает недоступность данных и не раскрывает имена узлов, адрес брокера,
названия неизвестных очередей, tenant-данные или тексты заданий.

## Надёжность выпуска

Рутинный native-релиз frontend CT137 переведён на один fail-closed controller.
Он проверяет точный source SHA, CI, артефакт, inventory, rollback и свободное
место до упорядоченного переключения выпуска и технического readback.

Frontend сохраняет работоспособность при поэтапном обновлении API и при
координированном откате: отсутствующие новые поля отображаются как недоступные,
а не приводят к падению страницы.

Render DEV теперь явно устанавливает async-вариант SQLAlchemy. Release gate
сопоставляет его независимый `requirements.txt` с основными зависимостями API и
останавливает выпуск до runtime, если обязательный пакет снова потерян.

## Техническая граница

- Миграция базы данных не требуется.
- Новые переменные окружения, тарифы и платные ресурсы не нужны. В Render DEV
  явно устанавливается уже используемая транзитивная зависимость `greenlet`.
- Маршруты задач, имена очередей, watchdog и существующие recovery-действия не
  изменяются.
- Обновляются frontend, API и три worker-контейнера единым exact-SHA выпуском.
- Предыдущий immutable release `v0.11.1` остаётся rollback target.

## Rollback

При неуспешном runtime readback вернуть CT137 frontend и VM126 API/worker на
сохранённые точные releases версии `v0.11.1`. Схема CT125 в этом выпуске не
меняется.
