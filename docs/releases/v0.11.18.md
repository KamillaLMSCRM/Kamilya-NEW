# Release Notes — 0.11.18

**Release date:** 2026-09-29

**Product version:** 0.11.18

**Git tag:** `v0.11.18`

## Added

- Covered employee, tenant-team and training-report operations now pass through
  one versioned privacy-processing policy and write a tenant-scoped, value-free
  processing record in the same database transaction as the business action.
- Unknown operations and role/policy mismatches fail closed at the shared policy
  boundary.

## Changed

- Runtime access to `audit_logs` is append-only. The application role keeps the
  access needed to insert and read records, while direct update and delete are
  revoked. The existing bounded tenant-purge function remains the deletion owner.
- Methodology chat, audience recommendations, learner assistance, question
  editing, job-description workflows and position recommendations now resolve
  AI providers with the active tenant identity.

## Security boundaries

- Processing records contain operation metadata, field names, data classes,
  purpose and decision outcome, but never field values or request payloads.
- Tenant-specific AI configuration no longer silently falls through to another
  tenant or to the platform provider chain at the affected user-facing routes.
- This release does not add blanket masking, change provider plans, alter model
  ordering, or send new customer data to an external service.

## Verification required

- Full API suite, focused privacy and tenant-routing suites, Python quality
  baseline, migration contract and single-head Alembic check.
- Exact-SHA CI, isolated Supabase DEV migration gate, DEV API/worker readback,
  then protected production migration and API/worker exact-SHA readback.
- A synthetic tenant smoke covering one privacy-ledger operation and one
  tenant-aware provider resolution without customer data.

## Operations

- Database migration: `0168` (revises `0167`; revokes `UPDATE, DELETE` on
  `audit_logs` from `lms_app`).
- Application rollback: immutable `0.11.17`; migration downgrade restores only
  the former `UPDATE` grant and intentionally does not weaken the earlier delete
  guard.
- Frontend source is unchanged, but the canonical product version remains
  synchronized across API and web manifests.
- No provider plan, billing, DNS, customer tenant, customer document or
  production AI-provider configuration mutation is authorized.
