# Release Notes — 0.5.35

**Product version:** 0.5.35

**Git tag:** `v0.5.35`

**Date:** 2026-09-14

## Для клиентов

- Если часть запланированных уроков не подтверждается исходным документом,
  Kamilya исключает эти уроки и продолжает проверять полезные, а не прерывает
  весь курс из-за сдвига внутренней нумерации.
- Исключённый слабый урок не создаётся повторно только ради заданного количества
  и не получает искусственный тест.
- После перезапуска прерванной задачи уже созданные уроки и тесты сохраняют
  связь со своими исходными темами.

## Технические изменения

- Введено терминальное состояние `omitted` для контрольных точек контента,
  рецензии и теста одного отклонённого планового урока.
- Причина отбраковки хранится как ограниченный серверный код без текста
  документа или ответа модели.
- Компактные координаты итогового курса переводятся обратно в неизменяемую
  идентичность исходного плана перед рецензией, сохранением и генерацией тестов.
- Миграция `0159` сохраняет RLS/FORCE RLS и существующие права роли приложения.

## Проверка выпуска

- RED-тест воспроизводит production-последовательность: второй урок отброшен,
  а третий становится вторым в итоговом курсе и раньше конфликтовал с чужой
  контрольной точкой.
- GREEN проходит генерацию, рецензию, тесты и финальную проверку полноты для
  трёх принятых и одного исключённого урока.
- Изолированный Supabase DEV gate проходит upgrade/downgrade/re-upgrade,
  конкурентный lease, терминальную отбраковку, RLS/FORCE RLS и cleanup без
  изменения публичной схемы DEV.
- После exact-SHA deployment выполняется свежий production-путь методиста по
  документам ломбарда с замерами всех стадий и визуальной проверкой результата.

## Откат

Приложение откатывается на неизменяемые артефакты версии `0.5.34`. Миграция
`0159` перед возвратом ограничения переводит ещё не сохранённые терминальные
отбраковки обратно в `pending`; при повторном запуске старая версия заново
проверит только эти уроки.
