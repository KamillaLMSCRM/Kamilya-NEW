# Release Notes — 0.11.0

**Release date:** 2026-09-24

**Product version:** 0.11.0

**Git tag:** `v0.11.0`

## Для клиентов

В журнале обучения появился «Центр действий методиста». Он показывает только
актуальные проблемы текущего назначения: обучение не начато, остановилось,
просрочено либо обязательный тест ещё не пройден. Отдельно система предлагает
проверить вопросы, на которых ошибается значимая доля сотрудников.

Методист может зафиксировать напоминание, повторное назначение, дополнительный
материал или ручной разбор, указать срок и комментарий. Система сохраняет
исходное состояние и результат. Ручное завершение или отмена требуют пояснения,
а история действий не удаляет и не переписывает результаты обучения.

Центр не рассылает письма и не создаёт назначения скрытно: на этом этапе он
фиксирует проверяемое управленческое решение и его результат.

## Техническая граница

- Требуется additive-миграция `0163`.
- Новые переменные окружения, тарифы и платные ресурсы не нужны.
- Обновляются frontend, API и три worker-контейнера единым exact-SHA образом.
- Runtime-роль получает только ограниченные SELECT/INSERT и column-level UPDATE;
  удаление действий и изменение событий запрещены.
- Предыдущий immutable release `v0.10.2` остаётся rollback target. После
  применения `0163` откат приложения не требует downgrade схемы: новые таблицы
  additive и старый runtime их не использует.

## Проверка до выпуска

- API unit: 2100 passed; canonical runner contract: 1 passed.
- Frontend: 685 passed; typecheck, lint и production build PASS.
- Python quality baseline: Ruff 1050 / mypy 2221 без расширения допусков.
- Одноразовая Supabase DEV-схема: upgrade/downgrade/re-upgrade, tenant isolation,
  cross-tenant target/actor rejection, append-only events и cleanup PASS.

## Rollback

При неуспешном runtime readback вернуть frontend и API/worker на exact release
`v0.10.2`. Миграцию `0163` в production не понижать автоматически: таблицы
сохраняются как совместимые неиспользуемые данные до отдельного change control.
