# Release Notes — 0.11.83

**Product version:** 0.11.83

**Git tag:** `v0.11.83`

Source-document review now honors the existing audited
`source_preparation.max_tokens` setting for native DeepSeek requests. The
managed transport configuration, timeout, enabled thinking/reasoning and zero
automatic retries stay intact. The request identity includes the actual limit;
completed and unknown outcomes retain their existing recovery boundaries.

This corrects a production acceptance failure on the owner's original cash
instruction: the editor returned a fully received empty content string after
16,384 reported output tokens. The failed receipt, native images and prepared
parts are retained. This release does not accept that response or silently repeat
it. Changing the response ceiling uses the existing audited runtime-settings
interface and is distinct from deploying this routing correction.

No migration, new provider, resource, pricing plan or frontend design change.
Offline worker-path regressions cover 16,384 and 32,768 source limits, unchanged
managed timeout/reasoning and source-budget-bound request custody. Exact CI,
DEV, production and original-document acceptance are recorded separately in
the canonical handoff and test ledger; these notes alone do not establish them.
