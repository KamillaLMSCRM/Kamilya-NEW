# Release Notes — 0.6.2

**Product version:** 0.6.2

**Git tag:** `v0.6.2`

**Date:** 2026-09-17

## Для клиентов

- При добавлении сотрудника администратор может сразу создать новый отдел и
  обязательную должность в одной форме.
- Поле должности больше не блокируется, когда выбран вариант создания нового
  отдела; интерфейс поясняет, что должность будет создана вместе с сотрудником.
- Для существующего отдела по-прежнему можно выбрать уже созданную должность
  или добавить новую.

## Проверка кандидата

- Компонентный тест воспроизводит создание сотрудника вместе с новым отделом и
  новой должностью и проверяет точный запрос к штатному API.
- Отдельный тест подтверждает загрузку должностей выбранного существующего
  отдела.
- Полный frontend-набор, TypeScript, ESLint и профильные backend-тесты должны
  пройти для точного релизного SHA в CI.

## Безопасность и данные

- Используется существующий tenant-scoped endpoint ручного добавления
  сотрудника; правила tenant isolation, валидации и RLS не меняются.
- Реальные клиентские данные в приёмочных тестах не используются.

## Развёртывание

- Миграции базы данных и новые переменные окружения не требуются.
- API, workers и native frontend выпускаются из одного точного SHA.

## Откат

- Приложение можно вернуть на `v0.6.1` без изменения схемы базы данных.
