# Release Notes — 0.10.1

**Дата выпуска:** 2026-09-22

**Product version:** 0.10.1

**Git tag:** `v0.10.1`

## Для клиентов

В генераторе тестов усилена проверка вариантов ответа: неверные варианты должны
относиться к той же ситуации и тому же смысловому блоку, что и вопрос. Система
больше не добавляет слабые или повторяющиеся вопросы только ради заранее
заданного количества. Если исходного материала мало, тест остаётся короче, но
содержательнее.

При повторном открытии страницы генерации кабинет восстанавливает только задачу,
запущенную текущим пользователем. Начало новой генерации очищает прежний
завершённый результат и показывает состояние именно нового запуска.

В структуре сотрудников подразделения с одинаковыми названиями теперь
различаются по полному пути, например «Головной офис / Продажи» и «Филиал
Астана / Продажи». Вложенная структура не теряет допустимые одноимённые узлы.

Экран учебных циклов получил более понятные статусы, подсказки и пояснения к
повторным и корректирующим назначениям. В карточке tenant для суперадминистратора
отображаются фактические лимиты сотрудников и курсов без условных значений.

## Исправления доступа

Выход из режима просмотра tenant теперь восстанавливает исходную сессию
суперадминистратора одним атомарным действием. Во время переключения профиль
tenant не выдаётся за профиль суперадминистратора, а незавершённые AI-задачи не
подхватываются другим пользователем той же организации.

## Проверка качества

- Полный database-free набор API: 3063 теста пройдены, 54 явно помеченных
  integration-only проверки пропущены; отдельно API unit: 2084 теста пройдены.
- Полный web-набор: 124 файла, 676 тестов пройдены.
- Frontend lint, typecheck и production build пройдены.
- Изолированные Supabase DEV-гейты миграций 0160, 0161 и 0162 прошли; временные
  схемы удалены, cross-tenant и FORCE RLS проверки успешны.
- Реальный интеграционный тест superadmin/tenant прошёл на общей DEV-схеме
  `0162 (head)`.

## Развёртывание

- Новая миграция базы данных не требуется: выпуск использует существующую схему
  `0162`.
- Новые переменные окружения, платные ресурсы и изменения тарифов не требуются.
- Backend, workers и frontend должны быть развернуты из одного точного Git SHA;
  предыдущий immutable release сохраняется для отката.
