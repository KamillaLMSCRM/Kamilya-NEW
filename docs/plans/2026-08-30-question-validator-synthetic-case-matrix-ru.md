# Синтетическая матрица тест-кейсов для валидатора вопросов (Шаг 3)

**Назначение:** исходные данные для реализации Шага 3 плана
`2026-08-30-contextual-ai-editor-and-generation-quality-plan.md` — детерминированного
валидатора вопросов на уровне одного теста и целого квиза. Документ написан для
нетехнического методолога и автора тестов: каждая строка описывает, что
видит валидатор на входе, какой код проблемы он должен вернуть, блокирует ли
он публикацию, к какому полю относится замечание и какую формулировку увидит
методолог.

**Границы документа:**

- все вопросы и варианты — синтетические, на нейтральные темы; содержимого
  клиентов нет;
- проблема не создаётся правкой одного слова «в лоб»: там, где сигнал
  статистический (длина, стиль, позиция), тест-кейс задаётся распределением
  длин и формулировок, а не одним значением;
- валидатор — детерминированный гейт первого уровня. Он не оценивает
  методологическое качество и не «понимает» предметную область: он проверяет
  измеримые сигналы и явные структурные факты.

**Как читать поля таблиц:**

- **Сигнал на входе** — детерминированное свойство синтетического вопроса,
  которое вычисляется по содержимому без модели;
- **Код проблемы** — нормализованная метка из каталога качества
  (см. раздел 6.2 плана; расширение каталога допустимо, но фиксировано
  версионированным перечнем);
- **Блокировка** — `да` запрещает публикацию без явного override,
  `нет` — предупреждение;
- **Поле** — канонический путь поля, к которому привязано замечание;
- **Сообщение методологу** — закрытый каталог формулировок (не генерируется
  моделью);
- **Валидатор НЕ делает** — явный список выводов, которые запрещено делать из
  этого сигнала.

## 1. Сигнал длины правильного ответа (`correct_answer_length_signal`)

| Поле | Значение |
|---|---|
| Сигнал на входе | Вопрос: «Какой срок действия сертификата установлен внутренним регламентом?» Варианты: «30 дней» (30 знаков), «60 дней» (29), «90 дней» (31), и правильный «В соответствии с внутренним регламентом компании срок действия сертификата составляет 12 месяцев с даты выдачи» (95 знаков). Правильный длиннее медианы дистракторов более чем на 35%. |
| Код проблемы | `correct_answer_length_signal` |
| Блокировка | нет (предупреждение); блокирует только при систематическом повторении на уровне квиза — см. раздел 12 |
| Поле | `question.answer_options[3].text` (вариант, помеченный `is_correct=true`) |
| Сообщение методологу | «Правильный ответ заметно длиннее остальных. Обучающийся может угадать его по объёму текста, не зная темы. Сократите или выровняйте варианты.» |
| Валидатор НЕ делает | не утверждает, что ответ фактически неверен; не решает, какой вариант сделать правильным; не редактирует текст; не оценивает грамматику; не делает вывод о сложности вопроса. |

## 2. Стилистический сигнал правильного ответа (`correct_answer_style_signal`)

| Поле | Значение |
|---|---|
| Сигнал на входе | Три дистрактора — короткие именные группы («Складская накладная», «Акт приёмки», «Счёт-фактура»), а единственный правильный вариант — единственный, содержащий канцелярскую связку «в соответствии с пунктом» и единственный термин « регламентированный». Сигнал: маркер + термин встречаются только в одном варианте. |
| Код проблемы | `correct_answer_style_signal` |
| Блокировка | нет |
| Поле | `question.answer_options[i].text` (вариант с уникальным стилевым маркером) |
| Сообщение методологу | «Правильный ответ выделяется по стилю формулировки: только в нём встречается характерный оборот или термин. Переформулируйте варианты в одном стиле.» |
| Валидатор НЕ делает | не решает, какой стиль «правильный»; не приписывает вариантам смысловые различия; не утверждает, что термин ошибочен; не определяет, какой вариант должен быть дистрактором. |

## 3. Нереалистичный дистрактор (`implausible_distractors`)

| Поле | Значение |
|---|---|
| Сигнал на входе | Вопрос: «Каким документом оформляют приёмку товара?» Варианты: правильный «Акт приёмки», дистракторы «Праздничный торт», «График отпусков». Детерминированный сигнал: дистрактор не содержит ни одного ключевого термина вопроса и ни одного термина исходного фрагмента (нет пересечения по содержательным словам). |
| Код проблемы | `implausible_distractors` |
| Блокировка | да при полном отсутствии пересечения; предупреждение — при пересечении ниже порога |
| Поле | `question.answer_options[i].text` (каждый проблемный дистрактор) |
| Сообщение методологу | «Вариант „<текст варианта>“ очевидно не по теме. Обучающиеся выберут его, не зная материала. Замените на правдоподобную ошибку по теме вопроса.» |
| Валидатор НЕ делает | не генерирует замену; не решает, насколько вариант «разумен» содержательно; не оценивает юмор или этику; не удаляет вариант. |

## 4. Некорректная формулировка вопроса (`malformed_question`)

| Поле | Значение |
|---|---|
| Сигнал на входе | Текст вопроса обрывается: «Каким документом оформляют». Детерминированные сигналы: отсутствие вопросительного знака, отсутствие глагола-сказуемого в полной форме, длина менее нижнего порога, обрыв на предлоге. Каждый сигнал вычисляется отдельно. |
| Код проблемы | `malformed_question` |
| Блокировка | да |
| Поле | `question.text` |
| Сообщение методологу | «Текст вопроса обрывается или не законченный. Дополните формулировку до полного вопроса.» |
| Валидатор НЕ делает | не достраивает вопрос; не исправляет грамматику; не предлагает переформулировку; не отличает намеренно короткий стиль от обрыва — только сигналы незавершённости. |

## 5. Дубликат вопроса (`duplicate_question`)

| Поле | Значение |
|---|---|
| Сигнал на входе | В одном квизе два вопроса с одинаковым нормализованным текстом: «Какой срок хранения акта приёмки?». Второй экземпляр отличается только регистром и лишним пробелом. Нормализация: нижний регистр, схлопывание пробелов, снятие пунктуации. |
| Код проблемы | `duplicate_question` |
| Блокировка | да |
| Поле | `question.text` (второго из пары) + ссылка на ID первого |
| Сообщение методологу | «Этот вопрос повторяет вопрос №<N> в этом тесте. Оставьте один или переформулируйте так, чтобы проверялось другое знание.» |
| Валидатор НЕ делает | не удаляет дубль; не решает, какой из пары «лучше»; не объединяет вопросы; не переносит вопрос между тестами. |

## 6. Неподтверждённый правильный ответ при явных доказательствах (`unsupported_correct_answer`)

| Поле | Значение |
|---|---|
| Сигнал на входе | К вопросу приложены явные фрагменты источника `E01`: «Срок хранения акта приёмки — 5 лет». Правильный ответ: «3 года». Детерминированный сигнал: ни одно содержательное слово правильного ответа не пересекается с фрагментом, числовое значение отсутствует в источнике, и ни одна ссылка `source_quote_id` вопроса не содержит утверждаемого факта. |
| Код проблемы | `unsupported_correct_answer` |
| Блокировка | да |
| Поле | `question.correct_answer` (или `question.answer_options[i]` с `is_correct=true`) |
| Сообщение методологу | «Правильный ответ не подтверждается выбранным фрагментом источника. Проверьте ответ или выберите другой фрагмент источника, где этот факт есть.» |
| Валидатор НЕ делает | не определяет, какой ответ был бы правильным по источнику; не оценивает истинность вне данных фрагментов; не заменяет ссылку на источник; не смешивает «нет пересечения слов» с «факт неверен» — только «факт не выводим из приложенных фрагментов». |

## 7. Несколько явно поддержанных правильных ответов (`multiple_plausible_correct_answers`)

| Поле | Значение |
|---|---|
| Сигнал на входе | Вопрос: «Какой документ подтверждает приёмку товара?» Правильный «Акт приёмки», дистрактор «Накладная». Приложенный фрагмент источника `E02`: «Приёмка товара оформляется актом приёмки; допускается применение товарной накладной». Детерминированный сигнал: второй вариант также подтверждается приложенным фрагментом тем же критерием, что и эталонный. |
| Код проблемы | `multiple_plausible_correct_answers` |
| Блокировка | да |
| Поле | `question.answer_options[i]` (каждый подтверждаемый вариант) |
| Сообщение методологу | «Не только отмеченный вариант подтверждается источником. Уточните формулировку вопроса или правьте варианты, чтобы правильным был ровно один.» |
| Валидатор НЕ делает | не выбирает «наиболее правильный» вариант; не удаляет лишний; не решает методологический спор — фиксирует только детерминированный факт двойной подтверждаемости приложенными фрагментами. |

## 8. Только механическое запоминание (`rote_recall_only`)

| Поле | Значение |
|---|---|
| Сигнал на входе | Вопрос: «Сколько лет хранится акт приёмки по регламенту?» Полностью воспроизводит формулировку фрагмента `E01`, ответ — дословное число из фрагмента, вопрос не содержит ситуации, условия или действия. Сигналы: высокая лексическая близость вопроса к фрагменту, отсутствие глаголов действия/условия («выберите», «укажите ситуацию», «как поступит сотрудник»). |
| Код проблемы | `rote_recall_only` |
| Блокировка | нет (предупреждение) |
| Поле | `question.text` |
| Сообщение методологу | «Вопрос проверяет только запоминание формулировки из источника. Переформулируйте его в практическую ситуацию, если цель — проверка применения знания.» |
| Валидатор НЕ делает | не запрещает контрольные вопросы на знание факта — это продуктовое решение методолога; не оценивает важность знания; не создаёт ситуацию; не решает, какой тип вопроса «правильный». |

## 9. Языковая аномалия при явном несовпадении локали (`language_or_translation_problem`)

| Поле | Значение |
|---|---|
| Сигнал на входе | Локаль вопроса задана явно: `locale=ru`. Текст вопроса и вариантов — на казахском («Өнімді қабылдау қандай құжатпен ресімделеді?»). Детерминированный сигнал: скрипт/алфавит и частотный профиль текста не соответствуют заявленной локали. |
| Код проблемы | `language_or_translation_problem` |
| Блокировка | да |
| Поле | `question.locale` + `question.text` |
| Сообщение методологу | «Язык текста не совпадает с языком, выбранным для этого теста. Проверьте язык вопроса и вариантов.» |
| Валидатор НЕ делает | не определяет фактический язык с гарантией (только «не совпадает с заявленным»); не переводит текст; не оценивает качество перевода; не смешивает опечатки и смену языка — опечатки к этому коду не относятся. |

## 10. Утечка ответа в пояснение (`explanation_leaked_into_answer`)

| Поле | Значение |
|---|---|
| Сигнал на входе | Пояснение: «Правильный ответ — „Акт приёмки“, потому что…». Правильный вариант: «Акт приёмки». Детерминированный сигнал: пояснение содержит дословный текст одного из вариантов, при этом для остальных вариантов пояснение не даёт сопоставимого раскрытия. |
| Код проблемы | `explanation_leaked_into_answer` |
| Блокировка | да |
| Поле | `question.explanation` |
| Сообщение методологу | «Пояснение раскрывает правильный ответ до выбора. Уберите формулировку ответа из пояснения.» |
| Валидатор НЕ делает | не переписывает пояснение; не решает, где пояснение уместно раскрывать ответ (например, в режиме разбора после попытки это допустимо — код ставится только для текста, подаваемого до ответа); не оценивает полноту пояснения. |

## 11. Базовая линия «выбери самый длинный» (choose-longest)

| Поле | Значение |
|---|---|
| Сигнал на входе | Квиз из 10 вопросов. В 6 из 10 правильный ответ — самый длинный вариант (доля 60% > порога 50%). Стратегия «всегда выбирать самый длинный вариант» даёт 6 из 10 правильных (60%) при пороге прохождения 50%. |
| Код проблемы | `correct_answer_length_signal` (агрегат уровня квиза) |
| Блокировка | да при доле > 50% или при достижении базовой линией порога прохождения; предупреждение при доле > 40% |
| Поле | `quiz` (агрегат по `quiz.questions[*].answer_options[*]`) |
| Сообщение методологу | «В тесте правильный ответ чаще всего самый длинный. Тест можно пройти, выбирая самый длинный вариант, не зная темы. Выровняйте длину вариантов.» |
| Валидатор НЕ делает | не решает, какие вопросы чинить; не изменяет порог прохождения; не делает вывод о качестве каждого вопроса в отдельности — на уровне вопроса действует проверка из раздела 1. |

## 12. Чистый контроль (негативные кейсы)

Каждый кейз из разделов 1–11 имеет зеркальный чистый контроль. Валидатор не
должен выдавать ни одного замечания по этим вопросам.

| Контроль | Что доказывает |
|---|---|
| Варианты сравнимы по длине: разница между самым длинным и самым коротким не превышает 25%, правильный — не самый длинный | Пороги длины не срабатывают на нормальных данных; раздел 1 — не «шумит» |
| Все четыре варианта в одном стилевом регистре: без канцеляризмов только в одном | Стилевой сигнал не срабатывает на однородных формулировках |
| Дистракторы содержат ключевые термины вопроса и правдоподобные ошибки («Товарный чек без подписи», «Устное распоряжение») | Проверка правдоподобия не отклоняет содержательные дистракторы |
| Полный вопрос: «Каким документом оформляют приёмку товара на складе?» | Проверка незавершённости не срабатывает на корректных коротких вопросах |
| Два разных вопроса об одном источнике с разной формулировкой и проверкой разных фактов | Проверка дублей не принимает тематическую близость за дубль |
| Правильный ответ дословно подтверждён фрагментом `E01` (число и термины совпадают) | Проверка подтверждаемости не срабатывает на подтверждённых ответах |
| Ровно один вариант подтверждён приложенным фрагментом; остальные опровергаются | Проверка кратности правильных не срабатывает при одном подтверждённом варианте |
| Практический вопрос-ситуация с глаголами действия и ответом-решением | Проверка механического запоминания не срабатывает на прикладных вопросах |
| Локаль `ru`, текст на русском; локаль `kk`, текст на казахском | Языковой контроль не срабатывает при корректной паре «локаль-текст» |
| Пояснение объясняет концепцию без формулировки вариантов: «Приёмка оформляется актом, который подписывают обе стороны» | Проверка утечки не срабатывает на пояснениях без текста вариантов |
| Квиз из 10 вопросов, где правильный — самый длинный в 3 из 10 (30%) | Агрегат choose-longest не срабатывает на сбалансированном квизе |

## 13. Граничные кейсы порогов

Пороги из раздела 4.1 плана (35% длины, 25% полезной детализации, 40%/50% доли
самого длинного) — продуктовые гипотезы и обязаны быть конфигурируемыми и
версионированными. Кейсы ниже фиксируют ожидаемое поведение на границах.

| Кейс | Ожидание |
|---|---|
| Правильный длиннее медианы дистракторов ровно на 35,0% | Нижняя граница предупреждения: замечание выдаётся (правило «более чем на 35%» трактуется как `>= 35%`; точная семантика границы фиксируется в тесте порога) |
| Правильный длиннее медианы на 34,9% | Замечания нет |
| Два дистрактора в пределах 25% полезной детализации правильного | Требование раздела 4.1 выполнено, замечания нет |
| Только один дистрактор в пределах 25% (требование — минимум два) | Предупреждение о длине |
| Доля «правильный — самый длинный» ровно 40% | Предупреждение уровня квиза |
| Доля ровно 50% | Блокировка уровня квиза (правило «превышает 50%» трактуется как `>= 50%`; семантика границы — в тесте) |
| Доля 49% при пороге прохождения 50% и 10 вопросах: стратегия «выбери самый длинный» даёт 5 из 10 (50%) — базовая линия достигает порога | Блокировка по условию «базовая линия достигает порога прохождения» |
| Доля 40% и стратегия «выбери самый длинный» даёт 4 из 10 (40%) при пороге 50% | Предупреждение, без блокировки по базовой линии |
| Конфигурация с изменёнными порогами (например, 30%/45%) применяется к тем же кейсам | Результаты меняются строго по новой конфигурации; версия конфигурации валидатора сохраняется рядом с результатом |
| Старая и новая версии конфигурации прогоняются на одной матрице | Совпадение результатов по старой версии и ожидаемые расхождения по новой; результаты нельзя перезаписывать задним числом |

## 14. Требования к хранению результатов

- Каждый результат проверки сохраняется с версией валидатора и версией
  конфигурации порогов.
- Замечание всегда содержит: код проблемы, блокирующий/неблокирующий статус,
  путь поля, идентификатор вопроса и закрытую формулировку сообщения.
- Сообщения каталогизируются: один код — одна каноническая формулировка на
