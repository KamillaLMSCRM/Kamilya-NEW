# План: evidence P0 и dry-run документов ломбарда

Дата: 2026-07-30

## Цель

1. Начать реализацию общего юридически доказуемого ядра Kamilya LMS.
2. Прогнать два документа первого ломбарда через текущий flow загрузки,
   индексации, генерации курса и тестов в изолированном тестовом контуре.
3. Зафиксировать результат, ограничения и готовность к созданию реального
   tenant на следующей неделе.

## Ограничения

- Не создавать боевой tenant ломбарда в этом проходе.
- Не смешивать документы ломбарда с демонстрационными источниками.
- Не заявлять внутренний тест как официальную аттестацию, допуск или
  официальный сертификат.
- Не выводить содержимое секретов.

## Этапы

### 1. Инвентаризация

- [ ] Сверить `master` с `origin/master`.
- [ ] Через Graphify и исходники проследить публикацию курса, назначения,
  попытки тестов, загрузку документов и AI generation.
- [ ] Проверить состояние миграций и тестовой инфраструктуры.

### 2. Документы ломбарда

- [ ] Извлечь и визуально проверить PDF.
- [ ] Конвертировать старый `.doc` только во временный читаемый формат и
  проверить содержимое.
- [ ] Определить рекомендуемое назначение каждого источника, аудиторию,
  структуру курса и риски смешения тем.
- [ ] Загрузить каждый документ отдельно в тестовый контур.
- [ ] Дождаться реальной индексации.
- [ ] Сгенерировать отдельный курс и тесты для каждого источника.
- [ ] Проверить source traceability, язык, фактические ошибки и
  юридически опасные формулировки.

### 3. P0.1 — неизменяемый релиз и снимок попытки

  `ContentRelease`.
- [ ] Добавить снимок структуры курса и хеш при публикации.
- [ ] Привязать новые назначения к релизу без ломки существующих записей.
- [ ] Добавить полный snapshot тестовой попытки.
- [ ] Запретить тихое изменение доказательной истории.
- [ ] Добавить tenant/RLS/FORCE RLS и cross-tenant тесты.

### 4. Проверка

- [ ] Graphify update.

### 5. Выпуск и документация

- [ ] Обновить ADR, внутреннюю документацию, readiness и backlog.
- [ ] Удалить этот временный план после переноса устойчивых результатов.

## Gate

Этап считается закрытым только при наличии:

- реального результата генерации по обоим исходным документам;
- воспроизводимых автоматических тестов для новой модели доказательств;
- подтвержденной миграции и production revision;
- отсутствия межтенантного доступа к релизам и снимкам попыток.
