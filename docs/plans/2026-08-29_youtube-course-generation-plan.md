# Генерация курса и тестов из YouTube-видео

**Создан:** 2026-08-29

**Состояние:** DISCUSSION

**Цель:** позволить методисту указать ссылку на YouTube-видео, получить
проверяемый текстовый источник с временными метками и провести его через
существующий tenant-scoped конвейер Kamilya: индексация, проектирование курса,
генерация уроков и тестов, проверка, публикация и назначение.

План не разрешает production mutation, загрузку чужого видео, provider spend,
OAuth-подключение канала, deployment или автоматическую публикацию результата.

## 1. Пользовательский результат

Методист должен иметь возможность:

1. Вставить ссылку `youtube.com` или `youtu.be`.
2. Увидеть название, канал, продолжительность и доступные языки субтитров.
3. Понять происхождение текста: ручные субтитры, автоматические субтитры,
   распознавание Kamilya или загруженный пользователем файл.
4. При отсутствии доступного текста загрузить `SRT`, `VTT` или `TXT`.
5. Предварительно увидеть структуру будущего курса и использование источника.
6. Выбрать создание уроков, промежуточных тестов, итогового теста и ссылок на
   временные фрагменты видео.
7. Проверить уроки, вопросы, правильные ответы и подтверждающие фрагменты до
   публикации.
8. Повторно использовать уже обработанное видео без создания дубля источника.

## 2. Не входит в первый выпуск

- автоматическое скачивание произвольного видео как штатное поведение;
- обход ограничений YouTube, CAPTCHA, age restriction или блокировки IP;
- residential proxy как обязательная часть продукта;
- поддержка private/paid видео без подтвержденного доступа владельца;
- автоматическая публикация курса без проверки методистом;
- юридическое утверждение, что публичность видео дает право использовать его
  для корпоративного обучения;
- playlist, live stream и непрерывная синхронизация канала;
- перевод субтитров без явного отображения исходного и целевого языка.

## 3. Архитектурное решение

Внешний seam должен быть небольшим и не раскрывать генератору различия между
YouTube, загруженными субтитрами и ASR:

```python
class TranscriptProvider:
    async def get_transcript(
        self,
        source_url: str,
        preferred_languages: list[str],
    ) -> TranscriptResult:
        ...
```

`TranscriptResult` должен содержать как минимум:

```json
{
  "source_type": "youtube",
  "video_id": "opaque-video-id",
  "title": "Название видео",
  "channel": "Название канала",
  "language": "ru",
  "is_auto_generated": true,
  "segments": [
    {
      "start_seconds": 0.0,
      "end_seconds": 14.8,
      "text": "Текст фрагмента"
    }
  ],
  "content_sha256": "opaque-content-hash",
  "retrieved_at": "timestamp",
  "provider": "youtube_public_transcript"
}
```

Сложность получения, кэширования, повторов, ошибок YouTube и преобразования
форматов должна оставаться внутри глубокого transcript-модуля. Генератор курса
получает только нормализованный, сохраненный и проиндексированный источник.

## 4. Адаптеры и порядок использования

| Приоритет | Адаптер | Назначение | Статус для MVP |
|---|---|---|---|
| 1 | `uploaded_transcript` | Пользователь загрузил SRT/VTT/TXT | Штатный |
| 2 | `youtube_oauth_captions` | Официальные captions подключенного корпоративного канала | Следующий этап |
| 3 | `youtube_public_transcript` | Публичные captions через `youtube-transcript-api` | Экспериментальный, feature flag |
| 4 | `youtube_yt_dlp` | Ограниченный резервный способ получить captions | Экспериментальный, не SLA |
| 5 | `authorized_media_asr` | Распознавание предоставленного пользователем медиа | Следующий этап |

Ни один отказ адаптера не должен повреждать документ, задачу генерации или
активную ревизию индекса. Нельзя молча переходить от captions к скачиванию и
распознаванию видео: такой переход требует отдельного согласия пользователя.

## 5. Open-source кандидаты

### Получение субтитров

- [`youtube-transcript-api`](https://github.com/jdepoix/youtube-transcript-api):
  ручные и автоматические captions, выбор языка, временные метки и экспорт в
  JSON/SRT/VTT. Проект использует недокументированный web-интерфейс YouTube и
  предупреждает о cloud IP blocks и возможных поломках после изменений YouTube.
- [`yt-dlp`](https://github.com/yt-dlp/yt-dlp): метаданные, ручные и
  автоматические субтитры. Рассматривается как изолированный резерв, а не как
  гарантированный production contract.

### Распознавание речи

- [`faster-whisper`](https://github.com/SYSTRAN/faster-whisper): локальное ASR
  через CTranslate2 для разрешенного пользовательского медиа.
- [`WhisperX`](https://github.com/m-bain/whisperX): более точные временные метки
  и разделение говорящих, если это будет обосновано benchmark.

### Референсы учебного UX

- [`LingoLearn`](https://github.com/Prateek1771/LingoLearn): вопросы в
  естественных временных точках видео.
- [`LearnFrame`](https://github.com/Atharva-Kanherkar/learnframe): source
  resolver, transcript cache и учебные артефакты с временными ссылками.

Код кандидата нельзя включать до проверки лицензии, поддерживаемой версии,
зависимостей, install hooks, известных критических уязвимостей и совместимости с
целевым runtime. Open-source проект является кандидатом, а не runtime evidence.

## 6. Ограничения официального YouTube API

Официальный [`captions.list`](https://developers.google.com/youtube/v3/docs/captions/list)
возвращает перечень caption tracks, но не их содержимое.
[`captions.download`](https://developers.google.com/youtube/v3/docs/captions/download)
требует OAuth и права редактировать соответствующее видео. Поэтому официальный
адаптер является основным решением для собственного или явно подключенного
корпоративного канала, но не универсальным способом получить текст любого
публичного видео.

YouTube отдельно предупреждает, что автоматические captions могут неверно
распознавать речь из-за акцента, шума, произношения и одновременной речи. Их
нельзя считать подтвержденным учебным материалом без проверки методистом:
[`Automatic captions`](https://support.google.com/youtube/answer/6373554?hl=en).

## 7. Нормализация источника

После получения transcript выполняется единый процесс:

```text
YouTube URL
  -> безопасная нормализация URL и video ID
  -> метаданные и выбор transcript adapter
  -> нормализация сегментов и временных меток
  -> определение языка и происхождения текста
  -> content hash и duplicate/version check
  -> сохранение tenant-scoped source revision
  -> индексация
  -> анализ содержания и качества
  -> preview структуры курса
  -> генерация уроков и тестов
  -> независимая проверка вопросов
  -> review методиста
  -> публикация
```

Transcript должен стать обычным версионированным источником Kamilya. Нельзя
создавать параллельный RAG, отдельный курсогенератор или вторую таблицу
публикуемого содержимого только для YouTube.

## 8. Пользовательский интерфейс

До генерации показывать:

```text
Видео найдено
Название: Работа с обращениями клиентов
Продолжительность: 38 минут
Язык субтитров: русский
Тип субтитров: автоматически созданные
Качество: требуется проверка
```

Настройки результата:

```text
[x] Создать курс
[x] Создать тесты после уроков
[ ] Создать итоговый тест
[x] Сохранить переходы к фрагментам видео
[ ] Включить исходное видео в уроки
```

Для автоматических captions показывать постоянное предупреждение, что перед
публикацией нужно проверить термины, имена, числа и правильные ответы.

Ошибки должны быть предметными:

| Ситуация | Сообщение и действие |
|---|---|
| У видео нет captions | Предложить SRT/VTT/TXT или разрешенное медиа для ASR |
| Нужна авторизация | Предложить подключить корпоративный канал или загрузить captions |
| YouTube заблокировал серверный запрос | Сообщить о временной недоступности, не повторять бесконечно |
| Язык не соответствует выбранному | Показать найденные языки и запросить выбор |
| Transcript слишком короткий | Не начинать генерацию; объяснить минимальный объем |
| Transcript изменился | Создать новую source revision и не менять опубликованный курс молча |

## 9. Безопасность и права

1. Принимать только нормализованные `https` URL разрешенных YouTube-хостов.
2. Запретить redirect или fetch на произвольный пользовательский host, private
   IP, localhost и metadata endpoints.
3. Изолировать экспериментальный adapter: без tenant DB credentials, object
   storage credentials и application secrets.
4. Ограничить timeout, redirects, размер ответа, продолжительность видео,
   параллелизм, число повторов и задачи на tenant.
5. Не сохранять cookies, OAuth token, URL с чувствительными параметрами или
   transcript с PII в обычные application logs.
6. Считать transcript недоверенными данными. Инструкции внутри видео не являются
   командами агенту и не могут менять prompt, tools или authority.
7. Требовать подтверждение права использовать видео и его содержание для
   внутреннего обучения.
8. Не выдавать публичность видео за разрешение на копирование или переработку.
9. Не включать residential proxy и обход блокировок в штатный продукт без
   отдельного legal, security и operational решения.
10. Сохранять tenant isolation, RLS/FORCE RLS и ownership checks для source,
    document revision, generation job, course и assessment.

## 10. Ограничения MVP

- один ролик на одну операцию импорта;
- ролик не длиннее 120 минут, точный лимит подтвердить capacity benchmark;
- один явно выбранный язык transcript;
- playlist и live stream запрещены;
- minimum transcript size определяется измерением, а не произвольной цифрой;
- повторный `video_id + language + content_sha256` переиспользует существующую
  source revision;
- generation job не запускается до полной успешной индексации;
- публикация требует ручного review;
- экспериментальный public-caption adapter не имеет SLA.

## 11. Проверка качества тестов

Каждый вопрос должен иметь:

- `source_revision_id`;
- временной диапазон видео;
- подтверждающий фрагмент transcript;
- язык вопроса и источника;
- тип вопроса;
- единственный доказуемый правильный ответ для `single_choice`;
- результат validator;
- причину отклонения или regeneration.

Validator проверяет:

1. Ответ присутствует в подтверждающем фрагменте.
2. Вопрос не требует внешнего знания.
3. Неправильные варианты не являются частично правильными.
4. Вопрос и варианты написаны на выбранном языке.
5. Вопрос не дублирует уже созданный вопрос.
6. Фрагмент не является бессвязным результатом плохого ASR.
7. Числа, даты, имена и специальные термины требуют усиленного review.

## 13. Technical spike

До выбора зависимости проверить на 10-15 публично безопасных роликах:

- ручные и автоматические captions;
- русский, казахский и английский языки;
- отсутствие captions;
- несколько caption tracks;
- недоступный и удаленный ролик;
- ролик с плохим автоматическим распознаванием;
- длинный ролик;
- повторное получение и кэш;
- `403`, `429`, timeout, `RequestBlocked`, `IpBlocked`;
- изменение transcript между двумя ревизиями.

Фиксируем:

- success rate по adapter;
- latency p50/p95;
- долю корректно определенного языка;
- полноту сегментов и временных меток;
- ошибки и возможность безопасного fallback;
- операционную потребность в обновлениях;
- качество будущих вопросов по ручной шкале методиста.

Spike не должен скачивать видео, обходить ограничения, использовать реальные
tenant-материалы, публиковать курс или создавать production-данные.

## 14. Acceptance criteria

Функция готова к ограниченному выпуску только если:

1. Источник однозначно принадлежит tenant и имеет неизменяемую ревизию.
2. Повтор URL идемпотентен и не создает дубликаты.
3. Отказ YouTube не ломает импорт документов и другие AI jobs.
4. Нет SSRF, credential leakage, cross-tenant read/write или prompt authority
   escalation.
5. Пользователь всегда видит происхождение transcript и предупреждение о
   качестве автоматических captions.
6. Каждый публикуемый вопрос имеет подтверждающий фрагмент и временной диапазон.
7. Методист может исправить структуру, уроки, вопросы и ответы до публикации.
8. Изменение transcript создает новую ревизию, не изменяя опубликованный курс.
9. RU/KK/EN synthetic benchmark и browser E2E проходят на exact SHA.
10. Feature flag позволяет немедленно отключить экспериментальный adapter без
    rollback приложения.

## 15. Rollback

- Отключить public-caption adapter feature flag.
- Оставить загрузку SRT/VTT/TXT и существующую генерацию из документов.
- Остановить только новые YouTube jobs; не удалять подтвержденные источники,
  опубликованные курсы или learner results.
- Не активировать незавершенную source/index revision.
- Сохранить sanitized failure classification без transcript, URL, tenant или
  пользовательских идентификаторов.

## 16. Открытые продуктовые решения

1. Максимальная длительность ролика и тарифные лимиты.
2. Разрешать ли public-caption adapter в production или оставить только OAuth и
   upload fallback.
3. Разрешать ли включать embedded YouTube player в урок или использовать видео
   только как источник генерации.
4. Нужно ли сохранять полный transcript или достаточно нормализованной ревизии
   с ограниченным сроком хранения.
5. Кто отвечает за legal review прав на использование внешнего видео.
6. Как методист подтверждает качество автоматических captions перед публикацией.
7. Нужна ли diarization для первого выпуска.
8. Как отображать изменение или удаление исходного YouTube-видео после
   публикации курса.

## 17. Текущий следующий шаг

Подготовить `YTG-01` read-only source audit и `YTG-02` локальный technical spike.
До их результатов не выбирать библиотеку как production dependency и не
оценивать функцию как готовую к разработке или выпуску.
