# Обратная проверка качества генерации

Дата: 2026-09-23. Статус: локальная разработка; DEV и production не затронуты.

Цель: на синтетических источниках разной плотности проверять четыре согласованных с владельцем интерфейса по отдельности: тест по готовому уроку, урок по размеченному блоку, план курса по карте блоков, структура после разбора файла. Продукт не обязан создавать фиксированное число уроков или вопросов.

Источник истины для ожидаемых фактов — вручную размеченный `apps/api/tests/fixtures/course_generation_backward/corpus.json`, не ответ генератора. Клиентские документы и персональные данные не включаются.

## Обратная лестница

1. Для каждого вопроса — один источник, однозначный ключ, тематические и неверные альтернативы, отсутствие дубликата факта. Допустим ноль вопросов, если блок не проверяем.
2. Для урока — связная тема, сохранение важных условий и исключений, отсутствие чужих сведений. Число уроков ограничивает число независимых тем.
3. Для плана — первичные блоки дают учебные темы; вспомогательные каталоги дают примеры, но не создают уроки сами по себе.
4. Для файла — сохраняются заголовки, строки/таблицы, порядок, происхождение и неопределённые значения.

## Этапы и приёмка

- Красный тест на одном правиле: источник с одной темой не должен исчезать как `supporting`.
- Красный тест на основном и вспомогательном листах: номенклатура не должна давать самостоятельные уроки при наличии листа «Коллекции».
- Зелёные focused tests для всей базы и старых source/plan/assessment регрессий.
- Отдельные интерфейсные проверки урока и вопроса на тех же золотых фактах; при сбое — минимальное изменение только владельца соответствующего модуля.
- Перед любым выпуском — `AI-COURSE-01` и DEV gate по каноническому контракту. Этот план не разрешает release.

## Границы

Работа идёт в отдельном worktree от `master` SHA `6ad718bf94217ad35c0f4ef5a3b622b03aaa31ef`, потому что основное дерево содержит незавершённые изменения в AI-файлах. Без tenant DB, клиентских файлов и production/DEV-записей. Владелец отдельно разрешил не более 8 вызовов существующего DeepSeek-аккаунта на синтетических данных с пределом дополнительного расхода $2, без смены тарифа. Этот предел исчерпан, новые платные вызовы в рамках эксперимента запрещены. Не менять legacy-ветку генерации, маршруты, роли, очереди, авторизацию и публичные контракты. Новая потребность изменить соседний модуль требует дополнения impact matrix.

## Результат

Для каждого сценария зафиксировать: сохранённые/потерянные факты, число первичных и вспомогательных секций, уроков и вопросов, конкретные нарушения. Живой образец на одном правиле описать отдельно; не называть зелёную детерминированную проверку или один образец доказательством 9/10 качества на сложных документах.
