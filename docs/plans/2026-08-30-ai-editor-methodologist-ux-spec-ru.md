# UX-спецификация контекстного AI-редактора для методолога

**Статус:** черновик-спецификация для обсуждения. Документ только о текстах,
состояниях и поведении интерфейса. Он не описывает реализацию и не меняет
утверждённый план
[`2026-08-30-contextual-ai-editor-and-generation-quality-plan.md`](2026-08-30-contextual-ai-editor-and-generation-quality-plan.md).

**Дата:** 2026-08-30

**Целевой пользователь:** методолог без технической подготовки (сотрудник HR,
бизнес-методолог), который проверяет и правит сгенерированные AI курсы и тесты.

**Роль в системе:** спецификация ориентирована на `methodologist`
(каноническую роль Kamilya). Доступ к экрану управляется продуктовым контрактом
ролей и прав и подлежит отдельному финальному решению; настоящая спецификация
не исключает доступ авторизованным tenant admin, если такой контракт будет
утверждён.

**Принципы спецификации:**

1. Ни одно изменение контента не происходит без явного подтверждения
   «Применить».
2. Методолог всегда видит, к какому именно объекту обращается ассистент.
3. Все примеры в этом документе — синтетические. Реальные тексты клиентов,
   персональные данные и содержимое tenant-ов в документ не включены.
4. Формулировки — на обычном рабочем русском языке, без технических терминов
   («patch», «идемпотентность», «оптимистическая блокировка» и т.п. в UI не
   используются).

## 1. Контекст выбранной цели (selected target)

### 1.1 Поведение

Перед вводом запроса панель ассистента всегда показывает полный путь к
выбранному объекту по цепочке
`Курс → Модуль → Урок → Тест → Вопрос`. Путь виден постоянно: и когда
методолог вводит запрос, и когда читает результат. Мелькнуть и исчезнуть —
недопустимо.

Панель подсвечивает тип цели и её краткое имя:

| Тип цели | Отображение в панели |
|---|---|
| Курс | «Курс: Охрана труда для офиса (черновик)» |
| Модуль | «Модуль 1 из 2: Основы охраны труда» |
| Урок | «Урок 1.2: Электробезопасность» |
| Тест | «Тест урока 1.2» |
| Вопрос | «Вопрос 3 из 5» |
| Вариант ответа | «Вопрос 3, вариант Б» |
| Пояснение | «Пояснение к вопросу 3» |

### 1.2 Тексты

- Заголовок панели: **AI-помощник редактора**
- Подпись пути: **Вы редактируете:** `Курс → Модуль 1 → Урок 1.2 → Тест → Вопрос 3`
- Пояснение под полем ввода: **Изменения коснутся только этого вопроса.**
- Если выбрана более широкая цель (тест, модуль, курс): **Изменения могут
  коснуться нескольких элементов — проверьте список перед применением.**
- Если цель изменилась, а черновик запроса ещё не отправлен: **Цель изменилась.
  Проверьте, что вы редактируете нужный объект.** (см. раздел 10)

### 1.3 Пример (синтетический)

> **Вы редактируете:** Курс «Охрана труда для офиса» → Модуль 1 «Основы охраны
> труда» → Урок 1.2 «Электробезопасность» → Тест урока → Вопрос 3
>
> Изменения коснутся только этого вопроса.

## 2. Быстрые команды (quick commands)

### 2.1 Поведение

Под полем ввода — кнопки-чипы с типовыми запросами для выбранной цели. Нажатие
чипа сразу отправляет готовый запрос (без ручного набора) и показывает
подтверждение текста запроса перед запуском, если запрос длинный. Чипы
подставляются по типу цели:

| Тип цели | Чипы |
|---|---|
| Вопрос | «Добавить контекст», «Упростить формулировку», «Правдоподобные неверные варианты», «Одинаковая длина вариантов», «Сделать практическим сценарием», «Проверить по источнику» |
| Вариант ответа | «Переписать вариант», «Сделать короче», «Сделать подробнее» |
| Тест (все вопросы) | «Найти очевидные правильные ответы», «Найти повторяющиеся вопросы», «Проверить длину ответов», «Проверить связь с источником» |
| Урок | «Упростить абзац», «Добавить практический пример», «Проверить утверждения по источнику», «Сделать тест по уроку» |
| Курс | «Найти повторяющиеся темы», «Проверить структуру», «Проверить утверждения без источника» |

### 2.2 Тексты

- Заголовок группы: **Быстрые действия**
- Tooltip каждой кнопки совпадает с её надписью (дублирование не создаёт
  вопросов).
- После отправки чипа в истории запроса отображается полный текст запроса,
  как если бы методолог набрал его сам: например
  «Сделай неверные варианты правдоподобными, но явно ошибочными по источнику».

### 2.3 Пример (синтетический)

> Быстрые действия:
> [Добавить контекст] [Упростить формулировку] [Правдоподобные неверные
> варианты] [Одинаковая длина вариантов] [Проверить по источнику]

## 3. Свободные команды (free-form commands)

### 3.1 Поведение

Многострочное поле ввода принимает запрос обычными словами. Ограничений на
«правильный» формат нет: ассистент сам приводит запрос к нормализованной
категории действия. Если запрос выходит за границы возможного, ассистент
честно сообщает об этом (см. раздел 4).

Ограничения, которые видны методологу:

- поле принимает текст до 8000 символов; счётчик появляется только рядом с
  лимитом (после 7800 символов) и не отвлекает в остальных случаях;
- нельзя отправить пустой запрос;
- нельзя отправить новый запрос, пока предыдущий обрабатывается, — кнопка
  заменяется индикатором «Ассистент работает…».

### 3.2 Тексты

- Placeholder поля: **Например: сделай варианты ответов менее очевидными, но
  оставь правильный ответ без изменений**
- Кнопка отправки: **Спросить ассистента**
- Счётчик символов (виден только у лимита): **Осталось символов: 200**
- Обработка: **Ассистент работает… Обычно это занимает до минуты.**
- Подсказка под полем: **Ассистент предлагает изменения, но не применяет их
  без вашего подтверждения.**

### 3.3 Примеры свободных запросов (синтетические)

- «Упрости вопрос, чтобы понял новый сотрудник»
- «Вариант Б слишком очевидный — сделай все варианты похожими по длине»
- «Добавь в вопрос ситуацию из практики: сотрудник пользуется удлинителем»
- «Проверь, что правильный ответ правда следует из урока»

## 4. Обработка неоднозначных и невыполнимых запросов

### 4.1 Поведение

Ассистент не молчит и не «угадывает молча». Три реакции:

1. **Уточняющий вопрос** — когда запрос можно понять двумя и более способами,
   ассистент показывает 2–3 варианта трактовки и просит выбрать.
2. **Вежливый отказ** — когда запрос выходит за полномочия ассистента
   (например, требует удалить правильный ответ, изменить порог прохождения
   теста, трогать другой урок).
3. **Частичное выполнение** — когда выполнима только часть запроса; ассистент
   прямо называет, что сделано, а что нет.

### 4.2 Тексты уточняющего вопроса

- Заголовок: **Уточните, пожалуйста**
- Вводный текст: **Ваш запрос можно понять по-разному. Что вы имеете в виду?**
- Варианты трактовки — как выбираемые карточки, например (синтетика):
  - «Сделать вопрос практическим сценарием» — переписать вопрос как рабочую
    ситуацию;
  - «Добавить контекст к вопросу» — дописать вводную фразу перед вопросом,
    не меняя суть.
- Кнопка: **Выбрать** в каждой карточке.

### 4.3 Тексты вежливого отказа

> **Я не смогу это сделать.**
> Ассистент редактора не изменяет: правильный ответ без вашей отдельной
> команды, настройки теста (порог, число попыток), другие уроки и другие
> курсы. Попробуйте переформулировать запрос к текущему вопросу, например:
> «перепиши пояснение к вопросу».

### 4.4 Тексты частичного выполнения

> **Часть запроса выполнена.**
> ✅ Упрощена формулировка вопроса.
> ⚠️ Не выполнено: запрос «добавь пример из практики» требует источника.
> В выбранном документе подходящего примера не найдено.

## 5. Предпросмотр «до/после» (before/after preview)

### 5.1 Поведение

Результат работы ассистента показывается как сравнение двух колонок (на
мобильном — последовательно, с переключателем). Слева — текущий текст, справа
— предлагаемый. Изменённые фрагменты подсвечиваются. Контент не меняется до
нажатия «Применить».

### 5.2 Тексты

- Заголовок блока: **Предпросмотр изменений**
- Подписи колонок: **Сейчас** и **Предлагается**
- Легенда подсветки: **Жёлтым выделено новое, серым — удалённое.**
- Индикатор отсутствия изменений: **Предлагаемый текст совпадает с текущим.
  Нажмите «Другой вариант», чтобы запросить иное предложение.**

### 5.3 Пример (синтетический)

> **Предпросмотр изменений**
>
> | Сейчас | Предлагается |
> |---|---|
> | Какой документ регламентирует проверку удлинителей? | Перед подключением удлинителя на рабочем месте: какой документ определяет порядок его проверки? |
>
> Жёлтым выделено новое, серым — удалённое.

## 6. Источники (source evidence)

### 6.1 Поведение

Если у цели есть связанные документы-источники, предпросмотр показывает
фрагменты источников, на которых основано предложение. Каждый фрагмент можно
раскрыть. Название документа кликабельно и ведёт к документу в библиотеке
(права доступа — те же, что у методолога сейчас).

Если источника у предложения нет (например, запрос был про стиль формулировки),
блок источников скрыт, а не показан пустым.

### 6.2 Тексты

- Заголовок блока: **На чём основано предложение**
- Подпись к фрагменту: **Фрагмент документа «Название документа», раздел …**
- Если предложение не опирается на источник: **Это предложение меняет только
  стиль формулировки и не опирается на документы.**
- Если ассистент не нашёл подтверждение в источнике (для запроса «проверь по
  источнику»): **Подтверждения в выбранных документах не найдено. Проверьте
  утверждение вручную или выберите другие источники.**
- Предупреждение при отсутствии источников у цели целиком: **У этого элемента
  нет связанных документов. Ассистент будет опираться только на текущий текст.**

### 6.3 Пример (синтетический)

> **На чём основано предложение**
> ▸ Фрагмент документа «Правила работы с электрооборудованием (образец)»,
>   раздел 4: «Перед каждым использованием переносных электроустройств
>   сотрудник осматривает корпус и кабель…»

## 7. Предупреждения проверки (validation warnings)

### 7.1 Поведение

Перед показом кнопки «Применить» предложение автоматически проверяется
детерминированными правилами качества (см. раздел 4 плана). Результат проверки
показывается как список понятных предупреждений. Предупреждения делятся на:

- **некритичные** — «Применить» доступно, но методолог предупреждён;
- **критичные** — «Применить» заблокировано до изменения запроса; блокировка
  сопровождается объяснением и кнопкой «Изменить запрос».

### 7.2 Тексты

- Заголовок блока: **Проверка качества**
- Общий формат: `⚠ <суть проблемы> — <что с этим делать>`
- Примеры некритичных предупреждений (синтетика):
  - **Правильный ответ заметно длиннее остальных — варианты могут различаться
    по подробности. Проверьте или запросите выравнивание длины.**
  - **Правильный ответ повторяет формулировку урока почти дословно. Сотрудник
    может угадать ответ по стилю.**
- Примеры критичных предупреждений:
  - **Похоже, верных ответов два: «А» и «В». Применение заблокировано.
    Измените запрос, чтобы остался один верный вариант.**
  - **Неверный вариант «Г» не связан с темой урока и не запутает внимательного
    сотрудника — он слишком абсурден.**
- Кнопки при блокировке: **Изменить запрос** и **Отмена**.

### 7.3 Поведение после исправления

Если после перегенерации предупреждения сняты, блок показывает:
**Проверка пройдена. Предупреждений нет.**

## 8. Действия: Применить, Другой вариант, Отклонить, Отмена

### 8.1 Поведение

| Действие | Поведение |
|---|---|
| **Применить** | Видима только при отсутствии критичных предупреждений. Требует подтверждения, если цель — тест, модуль или курс (массовые изменения). После применения — краткое подтверждение и возврат к редактированию. |
| **Другой вариант** | Запрашивает новое предложение по тому же запросу. Текущий предпросмотр остаётся до прихода нового. |
| **Отклонить** | Закрывает предпросмотр без изменений. Предлагает необязательную причину (см. 8.2). |
| **Отмена** | Закрывает предпросмотр без изменений. Без вопросов о причине. |

### 8.2 Тексты

- Кнопки: **Применить**, **Другой вариант**, **Отклонить**, **Отмена**.
- Подтверждение применения (обычный случай, одна цель):
  **Изменения внесены.** Кнопка: **Понятно**.
- Подтверждение при массовой цели:
  > **Применить изменения к 4 вопросам теста?**
  > Изменения затронутут только перечисленные вопросы. Отменить их можно
  > будет через «Отменить последнее изменение» сразу после применения.
  > Кнопки: **Применить ко всем** / **Отмена**.
- Необязательные причины отклонения (один выбор, без открытого поля):
  > **Почему не подходит? (необязательно)**
  > ○ Не учла мой запрос
  > ○ Появилось то, чего нет в источнике
  > ○ Формулировка стала хуже
  > ○ Ответ по-прежнему очевиден
  > ○ Изменила слишком много
  > ○ Другое
  Кнопки: **Отправить** и **Пропустить**.
- Состояние обработки применения: **Сохраняю изменения…**
- Успешное чтение из хранилища после применения (состояние перечитано с
  сервера, а не из локального состояния): **Изменения сохранены.** с кнопкой
  **Отменить последнее изменение** (доступна ограниченное время, см. раздел 11).

### 8.3 Тексты ошибок применения

- Конфликт версий (пока методолог читала предпросмотр, текст изменился):
  > **Не удалось применить: текст изменился с момента предпросмотра.**
  > Кто-то редактировал этот вопрос (возможно, вы в другом окне). Запросите
  > предложение заново — ассистент учтёт текущий текст.
  > Кнопки: **Запросить заново** / **Отмена**.
- Сервис недоступен: **Ассистент сейчас недоступен. Изменения не применены,
  текст остался прежним. Попробуйте ещё раз позже.**

## 9. Защита несохранённого состояния (unsaved-state protection)

### 9.1 Поведение

- Введённый, но не отправленный текст запроса сохраняется при случайном
  закрытии панели, клике мимо и переключении вкладок редактора.
- Закрытие панели с черновым запросом не теряет текст: при повторном открытии
  панель показывает его же.
- Если у методолога есть неприменённый предпросмотр и он уходит со страницы
  редактора (или закрывает вкладку), система предупреждает стандартным
  браузерным диалогом. Формулировка внутри приложения:
  **Есть непросмотренные изменения ассистента. Уйти со страницы?**
- Внешний клик (вне панели) не закрывает панель с непустым черновиком и не
  закрывает модальные состояния разделов 7–8. Панель закрывается только
  явной кнопкой «Закрыть», Esc или когда черновик пуст.

### 9.2 Тексты

- Подсказка у свернутого черновика: **Восстановлен ваш не отправленный запрос.**
- Кнопка закрытия панели: **Закрыть**.
- Диалог ухода со страницы: заголовок **Неприменённые изменения**, текст
  **Вы не применили предложение ассистента. Уйти без применения?**,
  кнопки **Уйти** и **Остаться**.

## 10. Версионирование черновиков опубликованного курса

### 10.1 Поведение

- Если курс ещё не опубликован, изменения применяются к текущему черновику
  без создания новой версии.
- Если курс опубликован, любое применение изменения создаёт **новую черновую
  версию**. Опубликованная версия и все назначенные на неё сотрудники,
  их прогресс и результаты остаются без изменений.
- Панель ассистента всегда называет, к какой версии применяется изменение.
- Методолог видит понятный индикатор: сколько изменений черновой версии
  ожидают публикации.

### 10.2 Тексты

- Бейдж цели для неопубликованного курса: **черновик**.
- Бейдж цели для опубликованного курса: **опубликован — правки создадут новую
  версию**.
- Подтверждение при применении к опубликованному курсу:
  > **Курс уже опубликован.**
  > Изменения вносятся в новую черновую версию. Сотрудники, которые уже
  > проходят курс, продолжат по прежней версии — их прогресс и результаты
  > не изменятся.
  > Кнопки: **Создать черновую версию с изменениями** / **Отмена**.
- После применения: **Черновая версия создана. Опубликуйте её, когда
  проверите.** Кнопка: **Перейти к версии**.
- Напоминание в списке версий: **Черновая версия N: изменений от ассистента —
  3. Публикация доступна после проверки.**
- Историческая привязка (видна в карточке курса): **Сотрудники, начавшие
  курс ранее, остаются на версии, которую им назначили.**

## 11. Отмена изменения (undo)

### 11.1 Поведение

Отмена выполняется созданием новой ревизии, а не правкой истории. Кнопка
**Отменить последнее изменение** доступна сразу после применения и до
следующей ручной правки этого же элемента. Отмена возвращает текст к
предыдущему состоянию и также создаёт запись в истории версий.

### 11.2 Тексты

- Кнопка: **Отменить последнее изменение**
- Подтверждение: **Вернуть текст к состоянию до изменения ассистента?**
  Кнопки: **Вернуть** / **Оставить**.
- После отмены: **Изменение отменено. Предыдущий текст восстановлен.**

## 12. Доступность (accessibility)

### 12.1 Поведение и тексты

- Вся навигация по панели доступна с клавиатуры: Tab — переходы, Enter —
  отправка, Esc — закрытие панели (когда есть несохранённый предпросмотр,
  Esc сначала вызывает диалог раздела 9).
- У каждой интерактивной кнопки — доступное имя, совпадающее с видимой
  надписью; иконки снабжены текстовыми подписями для программ чтения с экрана.
- Сравнение «до/после» озвучивается как заголовок и две подписи колонок,
  а не только цветовая подсветка. Дублируем смысл подсветки словами
  «добавлено» / «удалено» в начале изменённого абзаца.
- Критичные предупреждения имеют текстовый префикс **Блокирующая проверка**,
  а не только красный цвет.
- Контраст текста и индикаторов соответствует WCAG 2.1 AA.
- Состояния загрузки озвучиваются: у индикатора обработки есть текстовая
  версия **Ассистент работает…**
- Фокус не «прыгает» при обновлении предпросмотра; после применения фокус
  переносится на подтверждение **Изменения сохранены.**

## 13. Поведение на мобильных устройствах

### 13.1 Поведение

- Панель ассистента на узких экранах разворачивается на всю ширину и
  открывается снизу как лист (bottom sheet), путь к цели и кнопки всегда
  видны без прокрутки.
- Сравнение «до/после» показывается последовательно с переключателем
  **Сейчас / Предлагается**; выбранный переключатель — две равные кнопки
  над текстом.
- Кнопки «Применить», «Другой вариант», «Отклонить», «Отмена» закреплены
  внизу листа и не исчезают при прокрутке.
- Ввод запроса — стандартная мобильная клавиатура; поле растёт по высоте до
  пяти строк, затем прокручивается.
- Быстрые чипы прокручиваются горизонтально одной строкой.
- Диалоги подтверждения (разделы 8, 10) на мобильном — модальные, с теми же
  текстами; «Отмена» всегда визуально отделена от подтверждающей кнопки.
- Подсветка различий дублируется подписями «добавлено»/«удалено», так как
  цветовые детали хуже читаются на маленьких экранах.

## 14. Согласие и прозрачность аналитики

### 14.1 Принцип

Ассистент может собирать обезличенную продуктовую статистику (что чаще просят
изменить, сколько предложений принято или отклонено), чтобы улучшать качество
генерации. Поведение по согласию, умолчанию и отключению аналитики требует
отдельного юридического и продуктового утверждения и в этой спецификации не
назначается. До такого утверждения телеметрический контракт записывает только
privacy-safe поля закрытых таксономий (тип запроса, версия, результат,
нормализованные метки) и никогда — текст инструкций или содержимое курса —
в кросс-тенантную аналитику. Текст инструкций и содержимое курса — данные
компании: они не попадают в общую аналитику и не показываются другим
компаниям.

### 14.2 Тексты первого показа (один раз, при первом открытии панели)

> **Как работает AI-помощник**
> Помощник читает только выбранный элемент курса и связанные документы вашей
> компании, чтобы предложить правку. Изменения вносятся только после нажатия
> «Применить».
> Для улучшения качества может собираться обезличенная статистика: типы
> запросов, принятые и отклонённые предложения. Тексты ваших запросов и
> содержимое курсов в общую статистику не попадают и другим компаниям не видны.
> Кнопки: **Понятно** / **Подробнее** («Подробнее» открывает пользовательскую
> документацию).
>
> Примечание: формулировки этого первого показа и поведение управления
> участием в статистике подлежат юридико-продуктовому утверждению.

### 14.3 Тексты раздела «О помощнике» (доступен из панели постоянно)

- **Что видит ассистент:** выбранный элемент, его путь в курсе, текущий текст
  и связанные документы-источники.
- **Что ассистент может:** предлагать правки по запросу и показывать
  предпросмотр до применения.
- **Чего ассистент не делает:** не публикует курсы, не меняет назначения,
  не трогает другие курсы и настройки тестов.
- **Данные и статистика:** в обезличенной статистике учитываются только тип
  запроса и его результат (принято/отклонено) из закрытых таксономий. Тексты
  запросов и содержимое курсов остаются внутри вашей компании.
- **Отозвать согласие / управление:** ссылка **Настройки статистики** —
  переключатель **Участвовать в обезличенной статистике качества**. Поведение
  по умолчанию (включён или выключен), порядок отзыва согласия и влияние
  отключения на работу ассистента подлежат юридико-продуктовому утверждению;
  до утверждения формулировка не назначается.

### 14.4 Прозрачность в моменте

- В предпросмотре рядом с источниками всегда видна строка версии генератора
  (мелким шрифтом, синтетика): **Предложение: генератор v7, проверка v3.**
  Эта строка служебная, но доступна методологу для отчета в поддержку.
- Приложение никогда не пишет в аналитику текст запроса; в интерфейсе это
  отражено фразой из 14.3 и не противоречит поведению.

## 15. Сквозной сценарий (синтетический)

1. Методолог открывает опубликованный курс «Охрана труда для офиса»,
   урок 1.2, тест, вопрос 3. Панель показывает:
   **Вы редактируете: … → Вопрос 3** и бейдж **опубликован — правки создадут
   новую версию**.
2. Методолог выбирает чип **Правдоподобные неверные варианты**.
3. Ассистент уточняет: **Уточните, пожалуйста** — «оставить правильный ответ
   без изменений?» Кнопки: **Да, оставить** / **Нет, переписать полностью**.
4. После выбора приходит предпросмотр с колонками **Сейчас / Предлагается**,
   двумя фрагментами источника и предупреждением
   **Проверка качества: 1 некритичное предупреждение** (длина ответов).
5. Методолог нажимает **Применить**. Система показывает диалог
   **Курс уже опубликован** (раздел 10.2). Методолог подтверждает.
6. Появляется **Изменения сохранены** и кнопка **Отменить последнее
   изменение**.
7. Через неделю методолог публикует черновую версию; сотрудники, начавшие
   курс раньше, остаются на прежней версии.

## 16. Таблица кратких текстовых конвенций

| Ситуация | Тон | Пример |
|---|---|---|
| Успех | короткое подтверждение без восклицаний | **Изменения сохранены.** |
| Предупреждение | суть + что делать | **Правильный ответ длиннее остальных — проверьте или запросите выравнивание.** |
| Блокировка | причина + выход | **Применение заблокировано. Измените запрос.** |
| Ошибка сервиса | статус данных + следующий шаг | **Изменения не применены, текст остался прежним.** |
| Неоднозначность | выбор из трактовок | **Ваш запрос можно понять по-разному. Что вы имеете в виду?** |
| Отказ | граница полномочий + альтернатива | **Ассистент редактора не изменяет настройки теста.** |

Общие правила:

- Обращение — на «вы» с маленькой буквы.
- Без канцелярита и англицизмов: «предпросмотр», а не «preview»; «применить»,
  а не «закоммитить».
- Кнопки — глаголы в инфинитиве или короткие глагольные формы («Применить»,
  «Отменить последнее изменение»).
- Не угрожать и не перегибать: вместо «Вы потеряете данные!» —
  «Есть непросмотренные изменения. Уйти со страницы?»
- Синтетические примеры во всех документах и тестовых сценариях; реальные
  тексты клиентов в UI-подсказках не используются.

Эта спецификация фиксирует тексты и поведение интерфейса. Следующие решения
намеренно не приняты в документе и требуют отдельного юридического или

| Решение | Статус | Что нужно утвердить |
|---|---|---|
