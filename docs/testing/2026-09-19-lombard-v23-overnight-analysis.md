## Почему статус пока не ГО

Ручная проверка артефакта после формально зелёного quality gate обнаружила:

1. В учебном тексте всё ещё присутствует OCR-хвост
   `др. ) Ломбарда...`. Новый preflight уже распознаёт такой фрагмент, но
   realization v23 был воспроизведён из trace v22, поэтому старый текст
   сохранился. Нужен чистый повтор затронутого урока без старого realization
   replay либо включение source fingerprint в ключ replay.
2. Два правильных ответа длиннее 260 символов: определение Залогового билета
   (370 символов) и обязанность сотрудников изучить Правила (280 символов).
   Они доказуемы и релевантны, но длина делает правильный вариант заметным и
   неудобным для чтения. Требуется обязательный deterministic length gate и
   атомизация/переформулировка оси до генерации вопроса.
3. `publishable=true` пока не учитывает качество уже реализованного текста
   урока и длину вариантов ответа. Формальный gate надо расширить этими двумя
   детерминированными проверками.

## Продолжение 19.09: исправление после анализа

Локально исправлены все три причины ложного зелёного статуса:

1. Lesson realization replay теперь требует SHA-256 канонического полного
   запроса. Legacy trace без fingerprint больше не может вернуть старый текст и
   уходит в явно настроенный live-fallback.
2. Итоговый gate распознаёт наблюдавшийся обрыв `др. ) Ломбарда...` в уроках и
   вариантах ответа, не блокируя обычное сокращение внутри скобок
   `(распоряжения, приказы и др. )`.
3. Правильный ответ ограничен 240 символами. Длинный вопрос удаляется без
   искусственного добора количества; определения вида `Термин — определение` и
   длинная обязанность сотрудника атомизируются до короткого exact source span.

## Финальная локальная приёмка на DeepSeek Flash

После недоступности ASUS генерация была явно переключена на дешёвую модель
DeepSeek `deepseek-flash`; скрытого fallback на другую chat-модель нет. Для
эмбеддингов продолжил работать `voyage-4-lite`.

Дополнительные исправления:

1. одинаковый длинный source-owned ответ больше не порождает повторные вопросы
   в разных уроках одной ревизии документа;
2. OCR-маркеры в перечне документов, удостоверяющих личность, очищаются без
   потери пяти элементов списка;
3. нормативные yes/no-вопросы получают серверный ключ и серверный обратный
   вариант, поэтому модель не обязана выдумывать несколько смыслово одинаковых
   отрицаний;
4. вводные деепричастные фрагменты без самостоятельной главной части, например
   `Получив информацию и ознакомившись ...`, не допускаются как правильный
   ответ; вопрос удаляется без искусственного восполнения количества;
5. constraint parser игнорирует лишнюю повреждённую цитату модели только тогда,
   когда для каждого первичного evidence fact присутствует отдельная точная
   валидная цитата; отсутствие первичной цитаты по-прежнему закрывает вопрос.
