# Original-source assessment completeness — V2

## Changed invariant

The number of questions follows independently source-owned learning targets,
not a per-lesson quota. Source completeness and generated-question quality are
separate gates: more targets cannot waive failed options or unsupported text.
The technical ceiling20 remains, with explicit missing/density audit.

Typed operational projections own exact source spans, complete actors,
conditions and source sentence indices. Mixed families use sentence-local
precedence. A recognized prefix does not cover independent suffix actions.
Unknown parenthetical predicates remain uncovered, never erased as context.
The internal OperationalStep/ExactSentenceSpan/OperationalProjection interface
has no database, provider, caller-authorization or role side effect.

A verified explicit prohibitive list can yield a whole-proposition binary
permission question. The mandatory prompt retains its source actor and the
entire action clause, including joint actions, time, conditions and exceptions.
No conjunction is distributed and no qualifier is stripped. The answer key is
the exact source prohibition predicate; its opposite is server-owned. Both
options still undergo the existing independent semantic and constraint reviews.
Provenance must revalidate the complete projection pair before materialization;
a bare non-list predicate cannot grant this path. Per-action prompt scope is
part of both axis identity and course-question dedup identity.

Binary projection is not a claim of high difficulty or a substitute for
scenario questions. Actual whole-course review must check repetitive keys,
answer cues, meaningful decisions and source coverage before production GO.

## Preserved interfaces and negative space

Existing QuestionDraft true_false/single_choice, course persistence, RBAC/RLS,
learner attempts/results and citation identities remain compatible. No schema,
public API, model routing, reserve activation, voice, OCR service configuration,
resource/tier or billing change. New policy marker evidence-v2-quality-v11
prevents reuse of old generation-stage outputs as corrected output.

Legacy regeneration uses the existing runtime generation temperature, with
system instructions separated from retrieved source data. It still prepares
and validates before replacing any quiz and preserves rollback on failure.
Original document facts are never silently replaced by rewritten lesson text.

## Required evidence and stop conditions

Focused RED/GREEN, independent source review, full frozen API suite and Python
quality, exact-SHA DEV deployment, actual regeneration and fresh original-course
generation/manual/browser review. OCR corruption, ambiguous correct options,
critical missing targets or unresolved answer cues keep production NO_GO.
Only after quality acceptance: protected release, then the already-approved
exact two old unused QA-source deletions and hash-verified original reuploads.
