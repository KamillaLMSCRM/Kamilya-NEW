# Source preparation binds document parts and illustrations to existing approvals

The source review owns a single immutable selected working edition. Native text,
tables and image placements are represented by source-bound blocks and a complete
ordered partition. Model output proposes visual readings and part roles; it cannot
choose storage paths, invent asset identities or grant access.

Existing document_editorial_events analysis_block entries hold source-bound visual
responses, per-image readings, storage intents and the full prepared manifest.
Completed replies are reusable after failure, independent of regrouping. An
unconfirmed visual request stays unknown; no automatic repeat is made. Original
binary documents remain unchanged. New operational controls use runtime_settings
and its existing audit through additive constraint migration 0186.

Approvals include manifest identity and ordered selected IDs. Existing text-edit
spans remain relative to the compiled selected text; old approvals are reconstructed
using their historical payload shape, including optional page ranges. Generation
uses the pinned edition, never an unrelated fresh conversion.

Lesson markers are resolved only against the approved asset inventory. ContentBlock
metadata preserves the server descriptor in course release and approval snapshots.
Binary delivery checks exact author, enrollment/release or reviewer/attempt scope;
public projections omit internal storage keys. Historical snapshots block source
deletion. Derived cleanup follows committed storage intents and the same locked
usage guard. No new public object store or infrastructure is introduced.

Initial adapters cover native DOCX/PDF and recognized text from existing format
converters. Static PDF vector, form-XObject and annotation pages use bounded
pypdfium2 raster rendering; native scan bytes remain unchanged. Interactive
widgets fail explicitly. Rendering does not initialize form actions or scripts.

Image reading has an author and a pixel-based editorial verification stage.
The verifier receives the proposed reading and adjacent prose as untrusted data;
literal visible text and description remain separate. Completed malformed replies
have one addressed per-image schema correction, preserving valid siblings. Unknown
requests never repeat; a durable HTTP rejection is reconciled only against the
same original, exact batch membership and linked per-image intent.
